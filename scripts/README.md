## 一、233战法 全A盘前股池流水线（v1.7）

把「更新盘前股池」这件事固定成**一条命令 + 一份外置参数**。

### 文件

| 文件 | 作用 |
|---|---|
| `pool_pipeline.py` | 流水线主程序（采数 → 算指标 → 三筛选分层 → 导表 → 落盘 → 记台账） |
| `pool_config.json` | **全部参数**（阈值、数据源顺序、输出路径、免责声明）。改参数改这里，不改代码 |
| `backfill_daily.py` | 日线回补：给 `kline_metrics.json` 补上近 N 日日涨跌幅（`p5`/`ret5`）。**外部榜单匹配不上的题材靠它才有「自算 5 日涨幅」与「连续跑赢天数」**。5550 只约 60 秒，写回前自动备份 |
| `_初版归档/` | 首版一次性脚本，仅作过程留档，日常不再使用 |
| `../cache/pool_<数据日期>/` | 每次运行的中间数据（快照 / 日线指标 / 龙虎榜 / 涨停池 / 最终结果） |
| `../cache/pool_runs.csv` | 运行台账，每次追加一行，用于追溯「哪天的池子是用哪版参数生成的」 |

### 用法

```bash
PY=/Users/ccdemac/.workbuddy/binaries/python/envs/default/bin/python
cd /Users/ccdemac/Finance/AI顶级交易员

$PY scripts/pool_pipeline.py                    # 全量更新（约 1—2 分钟）
$PY scripts/pool_pipeline.py --reuse            # 复用缓存只重算+导表（约 0.2 秒，调阈值后重出）
$PY scripts/pool_pipeline.py --date 20261020    # 指定数据日
$PY scripts/pool_pipeline.py --out 路径.xlsx     # 自定义输出
$PY scripts/pool_pipeline.py --dry-run          # 只跑采数与统计，不写工作簿
$PY scripts/pool_pipeline.py --old-sheets       # 临时把 9-04 旧版 8 张对照表附在末尾
$PY scripts/pool_pipeline.py --sheets A0,A2,口径  # 只写这几张表（默认全写 8 张）
$PY scripts/pool_pipeline.py --reuse --cache-dir cache/pool_20261017   # 指定复用哪个缓存目录
```

**开关速查**：`--reuse` 复用缓存（改阈值后秒级重出）· `--date` 指定数据日 · `--out` 自定义输出 · `--dry-run` 不写工作簿 · `--old-sheets` 附旧版对照表 · `--sheets A0,A2,口径` 只写指定表 · `--cache-dir` 指定缓存目录 · `--config` 指定配置。

> **一行命令 = 整本重建，8 张表一起更新**，不是在原文件上改某几张（`Workbook()` 每次新建 → 逐张写 → `save`）。
> `--sheets` 只是**少写几张**，不会让剩下的表更新得更「准」，也**不要误读成「只有这几张变了」**——各表共享同一次采数的口径（市场基准、题材标签、产业链归链、主线簇），表间天然一致。

> **文件命名 = 数据日期，不是运行日期。** `233战法盘前股池_20261016.xlsx` 是「10-16 收盘数据、供 10-17 盘前用」。跨周末/节假日时用运行日命名会有歧义，所以一律用数据日期。

典型节奏：**每周或需要时全量跑一次；中途想试不同阈值，改 `pool_config.json` 后 `--reuse` 秒级重出。**

### 盘后标准序列（每个交易日收盘后，三步缺一不可）

```bash
$PY scripts/pool_pipeline.py          # ① 全量采数+出表（约 3.5 分钟）：快照/日线指标/龙虎榜/涨停池/题材/板块 → 8 张表 + theme_history 台账
$PY scripts/backfill_daily.py         # ② 日线回补（约 60 秒）：给 kline_metrics.json 补近 5 日日涨跌幅（p5/ret5）
$PY scripts/pool_pipeline.py --reuse  # ③ 重出工作簿（约 0.5 秒）：自算5日涨幅/连续跑赢/环节榜多日序列此时才齐全
```

**为什么必须三步**：①全量跑会**重建** `kline_metrics.json`（涨停次数/红肥绿瘦由日线直算），`p5/ret5` 序列是 ②事后补进去的——只有 ②跑完，③重出时「自算多日序列」才不是空列。漏掉 ②③ 的后果：`自算5日涨幅%`、`连续跑赢(日·自算)`、环节榜 5 日口径、317 个无外部读数题材的连续性**全部变空**。
⚠ ②不传 `--cache-dir` 时自动取**最新的股池缓存目录**（已修复：之前会误选台账文件 `pool_runs.csv` 导致崩溃）；跑完自动备份原文件为 `.bak<时间>.json`。

`theme_history` 台账在 ① 时追加当日快照——**每天跑一次，连续在榜/排名变化/生命周期才连得起来；漏一个交易日，排名线就断，连续性从 0 重数**（资金排名历史不可回补）。

### 两个口径要点（v1.2 由实战核验反例确立，详见熔炼系统 3.8 板块主口径＝题材）

**① 板块主口径是「题材」，不是「行业」**
233 说「先板块后个股」，那个板块是**资金正在炒的题材**。题材是跨行业的（低空经济横跨航空装备 / 汽车零部件 / 通信设备 / 军工电子），行业口径下会被切成碎片而丢失信号。
> 反例：2026-10-16 国防军工行业第一（+2.99%、涨 130/137），概念端无人机主力净流入 48.62 亿、低空经济 47.26 亿——但 v1.0 的股池用行业口径、且按「近20日涨停家数」排序，把航空装备Ⅱ / 地面兵装Ⅱ / 航海装备Ⅱ / 航天装备Ⅱ 压到第 50/68/114/119 位，**低空经济、无人机、军民融合这些题材名在表里根本不存在**。

**② 三筛选是绝对阈值，不能判定龙头**
三筛选只能证明「这票有涨停基因」，不能证明「它是这个题材的龙头」。233 的龙头六项全是**题材内部相对比较**。题材标签来源宽松（沾边即打标），只看绝对阈值会把「沾边且有基因的票」误当题材核心。
→ 因此窗口A「题材内领涨」按**龙头分**排序（`名·涨幅·龙xx`），龙头分 = 233 原文 3.2 六项（辨识度 / 涨停基因 / 5日线突破 / 成交量 / 涨速 / 板块带动性）在**题材内部**做百分位排名后加权。
**233 原文明确「涨得最快 ≠ 龙头」**：实测 无人机题材里 华力创通 +20.04% 但龙头分 85.0，宗申动力 +9.98% 龙头分 87.7——一日冲高的情绪脉冲排在了真正有量、有基因、能带动的票后面。
⚠ 边界：「板块带动性」用「个股涨幅 − 题材成分均涨」近似，真正的带动性要看个股涨停后板块是否跟涨，日频数据做不到——**近似不是等价**。

**②b 辨识度不能只看龙虎榜（v1.5 按 233 原文 2.2 重建为四类）**
旧口径用「近60日龙虎榜 ≥2」单代理 = 把「人气」当成辨识度的全部，且**完全没有「容量核心」**。按原文重建：

| 类 | 判定（阈值 C 级草案） | 补的是什么 |
|---|---|---|
| **前期龙头** | 最长连板 ≥3 或 近120日涨停 ≥6 | 市场记得它曾是龙头 |
| **人气股** | 龙虎榜 ≥2 或 当日换手 ≥8% 或 量比 ≥2 | 当日正在被讨论 |
| **容量核心** | 成交额 ≥8亿 且 流通市值 30—800亿 | **大资金进出得去**（游资与机构都能参与，不是一买就涨停的小票） |
| **反复活跃** | 近60日涨停 ≥4 或 近5日上涨 ≥4 天 | 不是一次性脉冲 |

命中 ≥1 类即达标，`辨识度构成` 列写明命中哪几类。⚠ 「龙虎榜 = 人气」只是人气的**一种代理**，不能等同于人气本身；「反复活跃」阈值刻意调高（zt60≥4）以避免与股性筛（zt60≥2）重合、使三筛选退化成两条。

**②c 产业链层级：板块 ≠ 题材，还可能是「环节」（v1.5 新增，诉求③）**
233 的「先板块后个股」里的板块，在产业链行情中往往是**某个环节而不是整条链**：5-6 月炒半导体动的是 材料→设备→存储→封测 的接力，CPO 行情里 光模块→光芯片→交换机 各走一段。
只看题材名 → 环节轮动被稀释在几百只的大标签里看不见；只看整条链 → 环节分化（材料强、封测弱）被抹平，还会误以为「整条链都在涨」。
→ 因此建立 **L1 链 → L2 环节 → L3 题材名** 三层（`config.chains`，11 条链）：

- **窗口A** 每行带「产业链 / 环节 / 过宽·可下钻为」三列；
- **窗口A2** 按「链 × 环节」重新聚合，四口径综合（当日超额 / 5日超额 / 涨停家数 / 成交额）；
- **环节通道**：环节榜前 8 名直接并入盘前焦点（档位标「环节」），与题材通道并列、互不挤占名额。

**为什么环节通道是必需的**：过宽母题材（>500 只）读数是稀释后的、不进焦点；而它的强子题材可能因为题材名冷门、绝对排名不够而进不了前 40——**两头落空**，这正是「半导体材料 / 设备 / PCB / MLCC / 交换机」这类细分在旧表里看不见的原因。

**链级大标签不是环节**：`军工` `半导体概念` `国产芯片` `人工智能` `电池技术` 这类覆盖整条链的泛标签（400+ 只）与真环节不可比，单列成「（链级·需下钻）」保留可见，但**不参与环节排名、不进焦点**，只作下钻入口。
⚠ 已用 `exclude` 修正误抢：`HJT电池 / TOPCon / BC电池 / 钙钛矿` 含「电池」会被新能源车链抢走，实为光伏技术，已让回光储风链；`生物识别 / 生物质能` 含「生物」会被医药链抢走，已让出。
⚠ 环节榜**缺资金列**：个股快照无主力净流入字段，题材级加总又会把重叠成分重复计算——宁可留空也不填一个会骗人的数。要看环节资金强度，回到窗口A 的「代表题材(资金最大)」列。

**③ 三条数据铁律（v1.3 由第二次实战核验确立，详见熔炼系统 3.9 五条数据铁律）**

| 铁律 | 反例（都是真发生过的） |
|---|---|
| **不静默删除** | 题材名与外部概念榜不完全相等就被 `continue` 丢掉 → 801 个题材只剩 240 个进表，`冰雪经济`（≠冰雪概念）、`白酒`（≠白酒概念）整类消失。改为三级匹配（原名→别名表→归一化去「概念/产业/板块」后缀→模糊前缀），匹配不到的**保留在表内**标「无外部读数」，并把**匹配方式写进表**（精确/归一/别名/模糊/无读数） |
| **排序必双口径** | 盘前焦点只按主力净流入取前 N（单口径）→ 冰雪经济主力仅 0.38 亿，但当日 +1.0%、涨 39/58、5 日超额 +4.03，永远进不了焦点 |
| **取前 N 必用多口径综合排名** | 「资金前 N ∪ 涨幅前 N」**仍是单口径思路**——每项都要么极端强才进得去。冰雪经济四项排名 90/62/**12**/85、白酒 55/99/29/102，**每项中等、没有一项极端的方向任何单口径都会漏**。改为多口径排名均值后稳定进榜。v1.5 起由四口径扩为**六口径**：资金 / 当日超额 / 5日超额 / 涨股比宽度 / **涨停家数（赚钱效应）** / **量比（量能承接）**。代价要认：会压低「单点极强但其余很差」的方向——盘前要的是「今天可能有钱去的地方」，不是「昨天最极端的读数」 |
| **强弱必相对** | 连续性用「当日涨 & 5 日涨」绝对正负判定 → 10-16 全市场 5 日 −5.19%，240 个题材被判成 151 首日 / 1 持续，字段当天失效。改为**相对全市场中位数的超额**（双正=持续，当日正 5 日负=首日），改后 持续 99 / 首日 90 / 走弱 206 |

涨幅榜入榜护栏：宽度必须「可用」且当日有涨停或池内有核心（否则成分 3 只的题材均涨再高也只是个股行情）；簇合计主力 ≤ −3 亿标「⚠资金流出」并沉底（涨幅强但资金大幅流出＝量价背离/派发嫌疑）。

### 全量 vs 固定数量：三层 + 两速（v1.2 采用的方案）

A股标签去重约 **1000+**（题材候选 717、行业 202、其余地域/风格/指数/事件）。处理策略不是「全量」也不是「固定 N 个题材」：

| 层 | 内容 | 数量 | 更新频率 | 是否固定 |
|---|---|---|---|---|
| **L0 标签库** | 全部题材 / 行业 / 风格标签 | 全部（717 题材） | **周度**（66 秒） | 否，全量索引 |
| **L1 候选榜** | 当日有资金读数、过粒度判据 | ~240（动态） | **每日** | **否，动态准入** |
| **L2 盘前焦点** | 聚类后的资金主线簇 | 前 N（config `focus.top_n`） | 每日 | **固定的是注意力预算，不是题材名单** |

关键取舍：

- **L0 全量保留**：标签只作索引（窗口C 明细的筛选列），不成行、不排序，成本可忽略。
- **L1 不设固定数量**：题材库本身每天在变（新概念随热点出现，如 DeepSeek概念、印巴冲突概念）。设固定名单必然漏新题材，这与 233「不预测只跟随」直接冲突。
- **L2 才固定数量**：人的注意力有限，盘前只需 8—12 个方向。

**L2 为什么按「簇」而不是按「题材」取**：同一波资金常有好几个名字（实测「无人机 / 军民融合 / 军工」是同一波的三个名字，合计主力 117 亿）。不聚类会让前排被同一方向霸占——看似 10 个方向，实际只有 3 个。
聚类度量用**当日强势股（涨幅 ≥5%）的重合度**，不用全体成分股：题材标签宽松导致成分股虚胖，全体重合度会被稀释（实测全体 Jaccard 一对都聚不出来，换成强势股才聚出军工簇）。

### 主线生命周期（窗口A 与 A0 的「生命周期阶段」列）

基于历史台账的「连续在榜天数」+「较昨日排名变化」自动判定：

| 阶段 | 判据 | 含义 |
|---|---|---|
| **启动(首日进榜)** | 连续在榜 = 0（昨日不在榜） | 3.4 要求 ≥2 日，首日**不加仓只观察** |
| **强化** | 连续在榜 ≥1 且排名上升 ≥3 | 资金在加码 |
| **维持** | 连续在榜 ≥1，排名基本持平 | 可跟，注意退潮信号 |
| **退潮** | 排名下滑 ≤−5，或主力净流入转负 | 不加仓，回到离场函数 |

阈值在 `config.lifecycle.rank_up_min` / `rank_down_max`（C 级待标定）。
⚠️ **边界**：这是**单个题材**的生命周期，**不等于**熔炼系统层2 的「板块演化链」（主线→溢出→切换→支线升主线）——演化链描述资金在板块之间的转移，需要板块间资金流对比，程序尚未实现。

### 待认领题材（窗口E）：防漏安全网

板块榜上有强资金（主力净流入 ≥`lifecycle.new_theme_min_zljlr` 亿）但我们的题材库里**没有这个名字**的概念。
成因多为**命名不一致**——实测实例：芯片概念 42.68 亿（库里有「国产芯片」）· 存储器 36.09 亿（「存储芯片」）· 中芯国际概念 18.64 亿（「中芯概念」）· 军工央企 / 军工集团 13.9 亿（「军工」）· 航空发动机 13.59 亿（「大飞机」）。

处理方式：用该概念的**领涨股**反查，看它是否已在我们池内、池层是什么、以及它在库内的等价题材是什么（同一列里能看到）。**每天扫一眼有没有陌生名字**，是防止题材库滞后于市场的最后一道网。

### 盘口质量 · 角色 · 梯队 · 情绪（v1.9，2026-10-23 熔入肉肉体系判据）

| 读数 | 量化自 | 判据 |

| **情绪条** | 肉肉 六② 情绪周期 | 涨停／炸板／炸板率／跌停（封死）／最高连板／连板家数 —— 层1 情绪冰点/高潮的量化输入。**炸板率＝（炸板池＋涨停里炸板后回封）/（涨停＋炸板池）**——只数炸板池会把剧烈分歧日误判成情绪正常（2026-10-23 实测 12.8% vs 真实 54.3%）；**跌停数用快照自算**（主板 9.7／创业科创 19.7／北交 29.7／ST 4.8），接口值单列「封死」 |

### 三条硬规则（已写进代码，不要绕过）

1. **参数外置**：所有阈值在 `pool_config.json`。改了参数要能被追溯，所以每次运行自动往 `cache/pool_runs.csv` 追加一行（含配置版本）。

   - 已踩过的坑：东财 `push2` / `push2his` 会**整段时间不可用**（2026-10-17 下午连续不通）。快照因此加了新浪 `Market_Center` 降级源；降级时工作簿「口径与来源说明」会自动多出一行 **⚠ 降级提示**（行业归属缺失 → 窗口A 板块列大面积落「其他」，量比/区间涨幅为空；涨停基因与红肥绿瘦由日线直算不受影响）。
3. **只产候选资格，不产买卖判断**：池层（核心/备选/观察）只决定「有没有资格进池」，**不决定仓位**。仓位由熔炼系统第五章方程决定；环境系数 <0.4 时 233 路径不出手；板块进攻但池内无标的 → 默认不追（3.6 出口规则二）。程序里没有、也不允许出现任何买点/卖点输出。

7. **时间窗**——ZigZag（ATR 倍数）自动分段的最后一个转折，距今天数与是否落在时间密码（±1）。
8. **量能**——基准指数成交量 vs 20 日均；≥1.25 倍且滞涨＝派发警报。

### 三条口径（C 级草案，可复算）

1. **身份来自主营构成，不来自标签顺序**：占比 ≥max(20%, 最大项×85%) 的主营项才参与归链，
   避免用 3.2% 的副业定义公司（实测：中基健康差点被 3.2% 的『种子』归进农业链·种业；
   海辰药业差点被 25% 的电解液添加剂归进新能源车链·电池）。
2. **归因用率不用家数**：`0.42×超额 + 0.18×涨停率 + 0.12×广度 + 0.10×焦点位 + 0.18×特异度`，
   再叠「主业同环节 +35 / 同链 +15 / 泛标签 −12」。大桶成分多、涨停家数天然多，只算家数会永远选出『人工智能』。
3. **两段式**：主业环节当日自己动了（≥55 分）就算答案；没动才允许归因到链外，并标红为外溢/蹭概念。
   这条让「启明星辰＝网络安全」「绿盟＝网络安全」「茅台＝白酒」「浪潮信息＝液冷服务器」都归到了正确环节。
4. **归链最长词优先**（2026-10-24 修）：`pool_pipeline.chain_of` 原先是「按 config 书写顺序首个命中」，
   于是 `AI应用链·应用` 环节词表里的裸词 `AI`（排在 `终端` 之前）会把『AI眼镜』『AI手机』『AIPC』
   全吃掉，`终端` 环节永远空着。改为**同链内取最长命中词、链间取最长命中词（同长保留书写顺序）**，
   与 `stock_profile.deep_match` 口径统一。全量 535 个概念标签只有 8 处变化，**8 处全是纠错**：
   `AI眼镜/AI手机/AIPC → 终端`、`转基因 医药→农业·种业`、`通用航空 航空→低空与无人机`、
   `家居用品/定制家居 消费链·—→轻工纺服·家居用品`、`工程机械概念→工程机械`。
   **反例留档**：`汽车芯片` 一度被新能源车链的长词拐走，已从该链的 match 与「智能化」环节摘除，
   归 `半导体链·设计`——链的选择不能只看词长，还要看词性属谁。
5. **泛词不许当身份判定词**（2026-10-24 体检，埃斯顿带出来的）：泛词只要在某个环节词表里，
   当主营项名含它时就可能压过真正的身份词，而且**最长词优先反而放大了风险**（越泛的词常常越长）。

   | 泛词 | 曾在哪 | 抢错了谁 | 处理 |
   |---|---|---|---|
   | `智能制造` | 软件与数据链·工业软件 | 埃斯顿「工业机器人及智能制造系统」→ 判成工业软件 | 删；改由 `机器人` 命中 → 机器人链·本体 |
   | `材料`（MATERIAL_KW 兜底） | 资源链·化工 | 「电子元器件及电子材料」「铜基合金材料」 | 删；材料类多数能靠环节词表自己命中 |
   | `铜`/`铝`（单字） | 资源链·工业金属 | 「镀铝纸」→工业金属、「铝塑膜」→非电池 | 删；补 铝制品/铝箔/铜箔/阴极铜/铜球/铜基合金 等具体词 |
   | `电力` | 公用事业链·火电水电 | 「电力电缆」「电力开关设备」「电力电子产品」 | **保留**（发电公司主营项就叫「电力」），靠补 `电缆/开关设备/电力电子` 到光储风链·电网 让最长词让路 |

   **教训**：删泛词前先跑「全量 1035 只主业 old/new diff」——`电力` 那次一删，
   9 家纯发电公司（粤电力/大唐/华能）全退回链级，比原来更差；正确做法是**补具体词**让最长词自己生效。
   **体检方法**：统计「第一顺位主营项的判定词 × 使用次数」，凡 ≤4 字且 ≥2 次的逐个人眼看，
   泛词就藏在里面（`材料` 26×、`电力` 15×、`工程` 17×、`自动化` 9× 都是这样翻出来的）。

**缓存**：`cache/profile/<code>.json`（增量，抓过就不再抓）。取不到就留空，不编造。

### 词表准入标准与自检（2026-10-24 Step1）

「最长词优先」有两个自己解决不了的死角，补两条规则堵住；再配一个自检脚本守住。

**规则一：`_归属绑定`（同一个词不许有两个家）**

**绑定的约束**：绑定不是"人工指定答案"，是"消除不可复现"——它不改变业务判断，只保证同一个词永远指向同一环节。
**且绑定的目标链必须在链级 `match` 里有这个词**，否则 `chain_of` 要求"先 match 命中才进链"，
绑定等于把这个词从题材层删掉（`激光雷达` 就这样掉给了军工链的「雷达」）。

df>25 的泛词实测 15 个，但**只有 5 个真的语义不收敛**，其余 10 个是"高 df 但语义准确"，不能一刀切：

   黄框逐条判断后要么修、要么写进 `_泛词放行` / `_环节保留` 并注明理由——**不许无视**。

### 行业 → 环节表 `_行业定环节`（2026-10-24 Step2）

**为什么先做这张表，而不是直接上 LLM**：326 只缺环节的票里，**270 只是「行业名认不出环节」**，
而申万三级行业名只有 **105 种**。判断 105 个名字，比逐票判断 326 只便宜两个数量级，而且
**一次判断永久有效、完全可复现、可审计**——这三条 LLM 都给不了。剩下 30 只才是真长尾。

**表结构**：`chains._行业定环节 = {"IT服务": "软件与数据链·行业IT", ...}`，183 条，覆盖三级名 + 二级名。
`main_seg` 按 **三级 → 二级 → 一级** 顺序查，命中即用。

**三个必须知道的实现细节**

1. **罗马数字后缀**：申万三级名带 `Ⅲ`/`Ⅱ`（`IT服务Ⅲ`、`中药Ⅲ`、`航空装备Ⅲ`），
   表按不带后缀的写法维护，查表前统一剥掉。不处理的话「IT服务Ⅲ」19 只全部查不到。

2. **二级名 / 一级名不许用来猜环节**（这条踩过）：
   `deep_match("食品饮料")` 含「饮料」→ 15 只乳制品/奶酪/火腿/速冻食品全归啤酒饮料；
   `deep_match("纺织服饰")` 含「纺织」→ 13 只男鞋/名表/钻石饰品全归纺织制造；
   `deep_match("传媒")` → 11 只演艺演出/物资销售全归数字媒体。
   **粗一级的行业名只用来定链，环节宁可留空**——留空是诚实地不知道，猜错是假装知道。
   代价是缺环节一度从 58 涨到 263，但这 263 只本来就在被猜错。

3. **主营项名只定到链时，借行业表补一次环节**（链必须一致）：
   「芯片销售」「智慧空间整体解决方案」「研发工程」这类项名只够定链、定不了环节，
   原先直接返回链级空环节，根本没走到行业兜底。33 只汽车零部件、16 只软件开发、10 只半导体都卡在这里。

| 房地产服务 | 地产基建链·房地产开发 | 15 只 | 物业≠开发 |
| 通信服务 | AI算力链·运营与卫星 | 38 只 | 含 IDC/通信工程 |

**判据**：二级名和「其他…」兜底桶，只在**与环节同名或语义等价**时才允许映射
（`一般零售→一般零售`、`其他养殖→养殖`、`其他生物制品→生物制品`）。
凡是「宽行业 → 窄环节」的一律删——它会把几百只票塞进一个环节，

（688836 / 002747 埃斯顿 / 300607 拓斯达）。

`电池→电池`、`汽车零部件→零部件`、`化学制药→化学制药`……


### 三个把「行业标签」整体搞坏的 bug（2026-10-24 修）

这一层不报错、不抛异常，只是**静默给出错答案**，所以三处都写进自检了。

**bug 1：地域锚点只认「…板块」，而内蒙古/黑龙江不写「板块」二字**

东财『所属板块』串的结构是「申万一级 二级 三级 **地域** …概念」，代码用
`x.endswith("板块")` 找切分点。但实测 5576 只里有 **64 只**的地域写成裸名
（`黑龙江` 37 只、`内蒙古` 27 只）——锚点找不到，于是：

- 行业标签整体为空 → 行业兜底整条失效
- **一级行业名和地域名一起被当成题材**：`汽车` `医药生物` `国防军工` `黑龙江`
  进了概念列表，去参与当日归因打分

修法：`kwrule.REGION_TOKENS`（34 个省级名）作为第二锚点，`load_tag_map` 与
`classify_tags` 共用。同时 `keep()` 里也要滤——裸地域名不以「板块」结尾，靠后缀滤不掉。

**bug 2：科创板/次新/大市值既没有「板块」也没有地域（实测 9 只）**

`688235 百济神州`、`600941 中国移动`、`688981 中芯国际`…标签串开头直接就是行业。
判据：`k is None and toks[0] in SW_L1` → 前 3 词仍是申万一二三级。
**必须先用一级行业名验证过才敢切**，否则碰到以概念开头的串会切错。

**bug 3：`IND2CHAIN` 把商贸零售/社会服务映射到不存在的「商贸社服链」**

19 条链里没有这条链，票被静默写进一个没有环节、不在题材榜的幽灵链，
错位度算不出来也不报错。现已改为 `消费链`，并在 `main_seg` 加了存在性检查
（`if ch not in chains: continue`），自检里也校验 `industry_to_chain` + `IND2CHAIN`
共 108 条的每个目标链是否真实存在。

**修复效果**：行业标签 59 只「空→有」、15 只「补全一级行业」、**丢失 0**。


### 逐票 `identity_override.json`（2026-10-24 Step2 后半）

19 链 / 108 环节是一套**有限**的分类体系，而 5000 多家公司的业务是无限的。
总有一批票的生意落在这套体系之外，规则无论怎么改都答不对——
**这时候正确答案是「体系覆盖不到」，不是硬塞一个环节。**

```json
"600202": {"name":"哈空调", "chain":"", "seg":"",
           "reason":"石化空冷器52.8%+电站空冷器26.4%，换热设备；19链无通用机械环节",
           "by":"人工", "conf":0.9, "asof":"2026-10-24"}
```

- **优先级最高**：`main_seg` 第一步就查它，压过主营词、行业表、经营范围
- **`chain`/`seg` 同为空串 = 已核实确认「不归链」**，与「还没查过」是两件事
- 只认 `code`；改任何词表都不影响它，它出错也只错那一只，不扩散
- 自检校验：链/环节名必须真实存在、必须写 `reason`、`conf < 0.7` 报警

**准入标准**（写进文件的 `_准入` 字段）：① 主营项名认不出 ② 行业名认不出或不唯一
③ 规则给的是错的链/环节 ④ 19 链确实没有对应环节时写空串并说明。

**27 条分两类**

| 类型 | 只数 | 例子 |
|---|---|---|
| 补环节 | 15 | 多氟多→新能源车·电池（六氟磷酸锂）、同飞股份→AI算力·数据中心（液冷）、亚玛顿→光储风·光伏（光伏玻璃）、味知香→消费·预制菜养殖 |
| 确认不归链 | 12 | 哈空调/冰轮环境/冰山冷热/雪人集团（工业制冷）、华测检测/天溯计量（第三方检测）、林州重机（煤机）、凯迪股份（电动推杆） |

**还剩 91 只「有链无环节」**，其中 **69 只全来自 `机械设备 → 机器人链` 这一条一级兜底**
（注塑机、色选机、针织横机、电梯、轨交信号、控制阀、超硬材料）。这些票的链本身是错的，
会把机器人链的强度读数拉偏。删不删这条兜底是**体系设计选择**（19 链要不要覆盖通用机械），
不擅自决定：删 → 未归链从 12 只涨到 ~81 只；留 → 覆盖面好看但机器人链不纯。
其余 22 只：AI算力链 10、半导体链 7、农业链 2 等，多为 IC 分销/物联网/外设这类
「链对了但没有贴切环节名」的情况。



### 东财 F10 主营构成：怎么才算「准确无误」（2026-10-24 深挖，大智慧带出来的）

这一层最容易出「看着对、其实空」的错。三个坑都踩过，记在这里：

**坑一：`secid` 把 92 开头的北交所代码拼成 `.SH`，接口静默返回 0 条**

```python
# 错：920207 → 920207.SH → zygcfx 0 条，不报错
if code.startswith(("6", "9")): return code + ".SH"
# 对：92 必须先判 BJ
if code.startswith(("4", "8", "92")): return code + ".BJ"
if code.startswith(("6", "9")):      return code + ".SH"
```

实测 `920207.SH` 返回 0 条、`920207.BJ` 返回 137 条。**静默失败**意味着缓存里留一条空画像，
前端显示「核心业务 —」，肉眼完全看不出是代码拼错。

**坑二：只取最新报告期 —— 半年报经常只有「按地区」**

接口一次返回 ~200 条，跨 20 多个报告期。实测 11 只空画像全部同一规律：
`2026-06-30` 只有 `MAINOP_TYPE=3`（境内/境外），`2025-12-31` 年报才有 `TYPE=2` 按产品。

大智慧（601519）就是典型：

| 报告期 | 有的口径 |
|---|---|
| 2026-06-30 | 只有 按地区：境内 77.0% / 境外 24.9% |
| 2025-12-31 | 按产品：金融资讯及数据PC终端服务系统 51.0% / 广告及互联网业务推广 14.7% / 港股服务系统 13.9% |

于是「核心业务」被写成「—」，主业只能靠行业兜底（≈软件与数据链），
再叠加归因「虚拟机器人 90」，最后输出一个「跨链蹭概念」——
**一个数据缺失被包装成了一个结论**，这比不显示更坏。

现在的选择顺序（`fetch_one`）：

1. 「有按产品」的最新一期（若比最新报告期旧 > 500 天则让位，避免用太陈旧的业务口径）
2. 「有按行业」的最新一期
3. 最新一期里剔除地区词后的剩余项
4. 全无 → 留空

并写进 `note`：「最新报告期 2026-06-30 只有按地区口径，取 2025-12-31 的按产品数据」，
看板在核心业务后面标 `〔2025-12-31报〕`，**不标就等于让读者以为是刚出的**。

**坑三：非业务项占比再大也不能当身份**

`其他(补充)` / `分部间抵销` / `合计` / `小计` / `其他业务` 要过滤（`JUNK_ITEMS`）。
大智慧的「分部间抵销 −2.1%」若不剔除会参与排序。

**行业三级名本身就能定环节**

原来行业兜底只给链、环节一律留空，等于把最准的信息扔了。申万三级里的
`机器人`/`消费电子`/`白酒`/`汽车零部件`/`软件开发` 本来就是环节词。
改法：命中行业后，再拿**该行业名**跑一次 `deep_match`，若链一致就把环节填上。
实测全池 504 只行业兜底里有 **221 只（44%）拿到了环节**，身份粒度从「链级」升到「链·环节」。

**兜底比例要如实公布**（全池 1036 只在案）：

| 证据来源 | 只数 | 占比 |
|---|---|---|
| 主营项名命中（算出来的） | 520 | 50.2% |
| 行业兜底（推的，含 221 只有环节） | 504 | 48.6% |
| 经营范围兜底（推的） | 11 | 1.1% |
| 未归链 | 1 | 0.1% |

**所以错位度必须带「≈」**：主业是推出来的，就标不出「主业驱动」这种结论性判断。
`attribute(..., main_approx=True)` 返回 `approx: True`，前端在错位度标签后加 `≈`
（`title` 里写「主业为行业/经营范围推定，错位度仅供参考」）。行业兜底那条链本来就跟着
申万行业走，归因撞上它是常态——不加标记，就是把假设当证据。

### 已接入的位置

- `intraday_board.py`（6060 实时看板）：盘口质量 / 机会候选 / 补涨候选 三张表都换成
  「核心业务｜今日归因（分）｜错位度｜主业链·环节」，启动时同步载入表内个股画像
  （`_preload_profiles`），其余池内票后台补。看板与 `profile_report.py` 共用同一套 `theme_attr` 打分，
  **口径不会两边漂**。
- `intraday_scan.py`（四时点快照）：仍用旧「题材定位」列，画像以 `profile_report.py` 出的单独一页为准。

### 盘口质量表的分组视图（2026-10-24）

问题：盘口表原来是「按成色从高到低」一列到底，同一题材的票被拆得七零八落，
看不出「哪个环节在抱团、哪个是单打独斗」。

现在盘口表上方有一条控件条（`#ctl`），两个维度可自由组合：

| 分组（`GRP`） | 键 | 说明 |
|---|---|---|
| `归因链→环节`（默认） | `chain_only` | 一级为链，链内再按环节插二级子标题（`tr.gs`） |
| `归因环节` | `chain`（链·环节） | 直接按环节聚，跨链同名环节不会混 |
| `归因题材` | `theme` | 最细，一题材一组 |
| `主业链→环节` | `biz` | 按**公司靠什么赚钱**聚（`≈` 前缀＝行业兜底，近似值） |
| `申万行业` | `ind` | 东财标签串前 3 词的申万一级 |

| 排序（`ORD`） | 规则 |
|---|---|
| `组内·成色`（默认） | 组间按组内最高成色；组内**先按环节聚块，块间按各自最高成色排**（不是按拼音），块内按成色 |
| `组内·归因分` | 组间仍按最高成色；组内纯按 `theme_attr` 归因分 |
| `由内到外（驱动→蹭概念）` | 组间按主导错位度（主业驱动→链内外溢→跨链蹭概念→未归链）；组内先按错位度再按成色 |

三条固定规则：

- **未归链永远沉底**（`（归因未归链）` / `（主业未归链）` / `（无行业）`），不参与组间排序竞争；
- **二级环节子标题只在「归因链→环节 + 组内·成色」时插入**。其余两种排序若仍插子标题，
  同一环节会被错位度/归因分打断成好几段、重复出现，宁可不插；此时组标题行右侧改显示「环节 名称+只数」；
- 组标题行（`tr.gh`）带该组的**错位度构成**（如 `主业驱动2/跨链蹭概念2/链内外溢2`），
  一眼看出这组是「真抱团」还是「一堆蹭概念的挤在一起」。

前端实现集中在 `intraday_board.py` 的 `renderPk/pkRow/segOf/mountCtl` 与 `GMODES/OMODES`，
`tick()` 只负责 `window.PK=pk; renderPk();`，不再直接拼表格。

## 四、题材口径：一票一桶（2026-10-24 修「题材龙头全变上海九百」）

### 报错现象

看板「补涨候选」表里，**固态电池 / 存储芯片**那一行的「题材龙头」显示的是 **上海九百**；
盘口表里同一行的「今日归因」和「该题材梯队」互相打架。用户原话：
「这些题材龙头为什么是上海九百？你确定这是对的吗？不止我列出的这两个，其他的你也需要去检查一下。」

### 三层根因（都不是数据错，是口径串了）

| # | 位置 | 问题 | 实测 |
|---|---|---|---|
| ① | `intraday_scan.py` pankou 行 | `题材 = code2themes[c][0]`（东财标签第一个，常是「一般零售」「长江三角」这类），而同一行「梯队」按**主归属**算 | 二者一致率 **2%**（80 行里 2 行） |
| ② | `intraday_scan.py` 补涨表 | 场景 key 来自 `ladder`（**标签全集**），龙头来自 `theme_head`（**主归属**）→ 两个分母 | 30 行里 **20 行**龙头「—」，其余从别的题材借（上海九百） |
| ③ | `pankou.py` ladder | 涨停家数按**标签口径**（一只票算进它挂的每个题材），判定却当板块效应用 | 华为概念 标签20家 → 主归属3家；长江三角 13 → 4 |

叠加结果：一只票有 6 个标签就开 6 个场景，场景是 A、龙头是 B、归因是 C，三者各说各话。

### 修法：桶成员只有一个定义

- **主归属题材**（一只票当日**唯一**身份）：候选＝该票标签中当日有涨停的题材 → **能归 19 链者优先**
  （属地/政策/重组类泛标签不抢身份：「固态电池」压过「长江三角」）→ 同级取涨停家数最多 → 覆盖更窄 → 名字序。
  非涨停票也照此归属（旧版只给涨停票算，这是②的源头）。
  参数在 `pool_config.json → intraday.attr`（`prefer_chain` / `min_n`）。
- **题材桶 ＝ 主归属该题材的票**（一票一桶，不重复计数）；**环节桶 ＝ 该链·环节成员**（业务位置，按标签归链）。
- **桶内一切读数同源**：`涨停 / 中军 / 龙头 / 判定` 都从同一批成员出。龙头＝桶内连板最高（并列取首封最早），
  与「总龙头/板块龙头/首板龙头」是**同一条规则**，所以不可能出现「梯队 3 家、龙头 1 板」。
- **`ladder` 同时存两个家数**：`涨停`（主归属，驱动判定）与 `涨停标签`（标签口径，参考）——
  两者差得越多，说明这个题材越是一堆票顺带挂了个标签。
- **补涨场景只用题材口径**（环节桶跨多个题材聚合，会把不同炒作逻辑混成一张表）。
- 页面与报告里，「梯队/龙头」格子**必须自带场景名**（`sceneCell`），读者不用猜是哪个题材的梯队。

### 改前／改后（同一份数据，2026-10-24 收盘，82 涨停 / 80 盘口行）

| 指标 | 改前 | 改后 |
|---|---|---|
| 盘口行「题材」与「梯队」同源 | 2% | **100%**（80/80） |
| 补涨「龙头」查不到 | 20/30（67%） | **0/9** |
| 补涨「龙头」不是该场景的人 | 3/30（且剩下多半也是借的） | **0/9** |
| 补涨「场景」≠ 本票主归属 | 未定义（场景取自标签全集） | **0/9** |
| 补涨表行数 | 30（含 21 行泛桶/无龙头） | 9（场景=一般零售3/军工3/机器人概念27，全有明确龙头） |
| 长江三角 涨停家数 | 13（标签口径，全市场上海股都算它的兵） | 4（主归属口径） |

紫竹高科／先导基电 的归属：改前都是「长江三角」，改后分别落到 **固态电池 / 国产芯片**。

改前数字是本次排查过程中的**实测输出**（`_audit_theme_head.py` 是修完才写的；项目无版本库，改前状态已无法用同一脚本复现）。改后完整输出留档在 `cache/_replay/audit_20261024_after.txt`。

### 代价（必须知道的副作用）

一票一桶会把「热度很高但没有主兵」的题材暴露出来：**本日 48 条焦点里有 19 条的涨停全被别的题材认领**，
焦点表将显示 `0家(标签3)·无主归属`（如减速器/机器视觉/机器人执行器）。
这是真实读数——它们是机器人主线的分支，分支内部没有独立龙头；旧版按标签口径会显示成「3家/成立」，
等于把别人的兵算成自己的。**不要再改回标签口径**：那会同时把「题材龙头」变成别家的龙头。
同理，`固态电池`（标签 7 家涨停）在主归属口径下 0 家——它的票被更宽的 `电池技术`（11 家）认领了，
所以它今天不构成补涨场景。**宁可场景少而准，也不要一只票同时当 6 个题材的兵。**

### 后续修正（同日，代价已消除）

上面那段「0家(标签3)·无主归属」的代价，**不是数据缺陷，是口径套错了地方**：焦点实时榜问的是
「这条主线今天有多少兵」（**篮子口径**），盘口/候选/补涨问的是「这只票的涨停算在谁的梯队里」（**主归属口径**）。
一开始把两处都换成了主归属，才出现 `0家(标签3)`。现在 `pankou._fill` 同时算两套：

| 口径 | 成员 | 用在哪 | 回答的问题 |
|---|---|---|---|
| 主归属（`涨停`/`中军`/`判定`） | 主归属＝该题材的涨停票 | 盘口、在动候选、潜伏候选、补涨 | 这只票算谁的兵 |
| 篮子（`涨停标签`/`中军标签`/`判定标签`） | 挂该标签的全部涨停票 | 焦点实时榜（HTML/看板/Excel） | 这条主线有多少兵 |

两套并存，但**同一个格子里只出现一套**。焦点表显示 `4家(主归属0)/3中军·成立`——
4 家是这条线的兵，括号里 0 家是「以它为主逻辑」的家数，差额被更具体的题材认领了。
改完后 `无主归属` 残留 = 0，`无主归属涨停` 兜底文案也改成了 `未成梯队`
（不写「0家」：ladder 不含全部题材，断言 0 家没有根据）。

## 五、行业兜底：一级行业不得单独定链（2026-10-24，删「机械设备→机器人链」）

### 问题

上一轮留下一个待拍板项：「`机械设备 → 机器人链` 这条一级兜底删不删？删了 69 只『有链无环节』变『未归链』，
不删机器人链不纯」。用户把决策权交给我（原话「这个老问题如何处理你来决定」）。查完证据后的结论是 **删**，
而且连带发现另外两处同源缺陷。

### 实测证据（1037 只有 F10 画像的票）

1. **这条映射指向的公司基本不是机器人**。命中它的 69 只，主营是：工业锅炉 92.7%（力聚热能）、
   冷却塔 64.4%（海鸥股份）、割草机 84.4%（大叶股份）、工业缝纫机 86.5%（杰克科技）、
   电梯部件 90.4%（同力天启）、破碎设备 36.2%（南矿集团）、钢绳 52.8%（贵绳股份）、液压油缸 48%（恒立液压）。
   只有 26/69 挂着机器人系概念（减速器/人形机器人/执行器），**另外 43 只连概念都不沾**。
2. **它的第二重危害比第一重更大**：那 26 只「主业电动工具/割草机/水泵、概念挂机器人」的票，
   本来正是「跨链蹭概念」的典型样本——而这条映射把它们的**主业也写成机器人链**，
   于是 `chainOff()` 永不触发 ⚠，等于把最值钱的错位信号抹平了。删掉它，信号才有机会出现。
3. **同族的另外两条也站不住**：`通用设备 / 专用设备` 两个键同样是杂项桶（含矿山机械/纺机/锅炉/楼宇设备）。
   申万三级里 542 只「机械设备」，只有 29 只下到「轨交设备Ⅱ」，其余连二级都没有——
   拿一级行业给它们定链，等于用「他属于机械行业」推断「他做机器人」。
4. **删除会掀开两条从未被检验过的兜底**（见下节「教训」）：
   - `材料/化工` 关键词兜底：旧版把所有主营项名拼成一个串做子串搜索，删掉 `机械设备` 后第一次生效，
     立刻把 利欧股份（0.2% 的『金属材料贸易』，主业传媒代理 80.7%）、铁科轨道（9.4% 的『工程材料』，
     主业轨道扣件 67.9%）、同力天启（『电梯部件及材料』90.4%，主体是电梯部件）判成资源链·化工。
   - `经营范围` 兜底（拿每条链的 match 词去搜工商登记原文）：全池命中数一直是 **0**，
     因为 `机械设备` 总是先返回。删掉后第一次生效，59 只里几乎全错——
     软件与数据链 12 只（杰克科技=缝纫机、卓郎智能=纺机、博众精工=3C 设备，经营范围里都有「软件」）、
     电子元器件链 7 只（山东威达=电动工具、大元泵业=水泵，都有「元件」）、
     地产基建链 3 只（铁科轨道=高铁扣件，有「建筑」）、传媒内容链 1 只（快意电梯，有「体育」）。

### 改法

1. 删 `pool_config.industry_to_chain` 与 `stock_profile.IND2CHAIN` 里的
   `机械设备 / 通用设备 / 专用设备 → 机器人链` 三条。保留 `自动化设备 → 机器人链`（同族，且确实偏自动化）。
2. **删掉「经营范围」兜底**。经营范围是工商登记的法律文本，写的是「**可以**做什么」，不是「靠什么赚钱」。
   拿它对全市场做子串搜索，等于用营业执照猜主业。19 链本来就不覆盖全市场，
   「主业未归链」是合法结论；需要更细的身份走 `identity_override.json` 逐票核实。
3. **收紧「材料/化工」兜底**：只认真正撑收入的主营项（≥max(20%, 最大项×85%)），
   材料/化工词必须**收尾**，且名称里不能带「部件/设备/整机/装置/系统/零件」——
   `超硬材料` 才是材料生意，`电梯部件及材料` 是部件生意。
4. 补 3 条人工 override（此前是被那条错误映射「蒙对」的）：中大力德 / 丰立智能 → 机器人链·零部件，
   昆船智能 → 机器人链·应用集成。理由与占比写进 `identity_override.json` 的 `reason`。

### 改前改后

| 指标 | 改前 | 改后 |
|---|---|---|

| 有链无环节 | 91 | **26** |
| 有环节 | 934 | 938（+3 人工 override +1 黄河旋风） |

剩下的 26 只「有链无环节」全是 `其他计算机设备 / 其他电子 / 其他农产品加工 / 其他金属新材料`
这类「其他X」三级名——链是对的，环节确实没有更细的信息，如实留空。

### 代价

**主业未归链从 12 涨到 73。** 这不是退步，是不再假装知道：锅炉、冷却塔、割草机、电梯、缝纫机、
破碎机、钢绳确实不属于这 19 条**题材链**中的任何一条。19 链是题材链，不是申万行业分类，
硬把「机械设备」塞进机器人链是为了让覆盖率好看，代价是让 69 只票的身份变成假的。

真正可惜的是那 4 只「自动化设备」还停在无环节状态（博众精工=3C 组装线、田中精机=非标机、
理奇智能=物料处理、宏英智能=工控），它们的环节要靠 override 逐只定，不靠猜。

### 教训（比结论更重要）

**兜底的优先级顺序，决定了哪些规则会被检验。**

`机械设备 → 机器人链` 排在最前面、覆盖面最大，它把 69 只疑难票一口气吞掉，

不是它们对，是它们从来没被调用过。看起来「两层兜底都在」，实际只有第一层在工作。

配套结论：**「配置里写了但从未命中」的条目要当成缺陷报出来**，不能当成「留着也没坏处」。

## 五之三、Step4：两栏显示 ＋ 纺织设备/轨交设备环节 ＋ 行业名不当主归属（2026-10-24 深夜）

用户把上一轮「刻意没做的三件事」「留给你决定」截图发回：「这三个图片上的问题你去再优化一下」。

### 落地 1：未归链拆两栏（身份列）

`未归链` 一个词混着两种性质完全不同的事，拆开：
- **非题材·已核实**（虚线灰徽章）＝人工核实过 19 链覆盖不到，理由悬停可见（来自 `identity_override.json` 的 ev）；
- **待补**（虚线灰徽章）＝规则还没覆盖到，随词表修订继续收敛。
判据：画像证据字段 `ev` 以「人工:」开头＝已核实。**注意：这不是把 57 只藏起来——每只仍占一格，只是性质分开。**

### 落地 2：轻工纺服链·纺织设备 ＋ 交运链·轨交设备（108 → 110 环节）

救回 8 只：泰坦股份/慈星股份/越剑智能/杰克科技（纺机缝纫）＋众合科技/康尼机电/祥和实业/铁科轨道（轨交装备）。
未归链 65 → 57。**词表教训（第一版踩了）**：
- 初版词『经编』『加弹』把**云中马**（主营『经编革基布』＝织造产品，不是设备）从纺织制造拽进了纺织设备——
  工序词会出现在产品名里。收紧为**整机名**：`纺纱设备/针织横机/大加弹/小加弹/加弹机/经编机/织造设备/纺织机械/缝纫机/缝制设备`。
- 『轨道交通』加共现门槛（必须含 产品/装备/设备/系统/零部件/制造/扣件/门）——隧道股份类『轨道交通施工』不是设备生意。
- 全池 diff：恰好 8 只，零误伤（`cache/_replay/identity_post_kw2.json` vs `identity_post_step4b.json`）。

### 落地 3：行业名永远不当主归属

实测缺陷链：大鹏工业 主归属=**专用设备**、四通股份=**其他家居用品**——申万行业名漏进题材列表，
被主归属规则当题材建桶（梯队/独苗全建立在假题材上）。三处同修：
- `pankou.roles_ladders` 自己重建的 code2themes 加 `block` 过滤（此前只过滤了外部传入的 t2codes，
  内部重建的那份没滤——修一处漏一处，这是本轮最大的教训）；
- `block`＝行业三级名全集（theme_attr.load_tag_map 的 ind 并集；rows['行业标签'] 只存一级名，不够）
  ∪ exclude_words（近期摘帽这类事件词也不许当主归属）；

## 五之四、主归属让位规则（2026-10-25 凌晨，用户核验归类后的规则级修复）

上一轮只把两口径分歧标了 ⚠，用户追问「怎么还是这样」——要的是归类本身改对。

### 规则

`pankou._main_of` 在 prefer_chain 之后加一步：**当归因层给出「涨的就是它自己的生意」的强证据
（layer=主业驱动 且 ≥55 分）时，主归属跟归因走**；归因题材不在该票标签里时，取**归因同链**候选中
家数最大者。护栏：layer=跨链蹭概念/链内外溢不触发（大业股份 46.9 跨链蹭概念 → 机器人概念 6 板
空间龙不受影响）；主业未归链的票无主业锚也不触发。
