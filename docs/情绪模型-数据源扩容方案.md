## 九、LLM 分类器上线（2026-10-20 深夜，第 3 步）

### 工具：`scripts/llm_label.py`

| 后端             | 触发方式                                                           | 成本                                            |
| -------------- | -------------------------------------------------------------- | --------------------------------------------- |
| API（OpenAI 兼容） | `export LLM_API_KEY=...`（可选 `LLM_BASE_URL` / `LLM_MODEL`）→ 跑脚本 | **2000 条约 ¥0.5—3**（gpt-4o-mini / DeepSeek 量级） |
| 标注缓存回填         | `--list` 导出清单 → 人工/会话标注 → `--apply` 回填                         | 免费（用时间换）                                      |

标注存 `cache/llm_labels/<hash>.json`；`sentiment_scan` / `sentiment_model` 分类时**自动优先读 LLM 标签**，没有才退回词表（已集成验证：日志会打印"分类器：N 条使用 LLM 标注缓存"）。

### 首轮 200 条实测（芯联集成/晶晨股份/立昂微，含大量业绩公告与情绪宣泄）

| 指标            | 结果                                           |
| ------------- | -------------------------------------------- |
| 词表 vs LLM 一致率 | **37.5%**                                    |
| **方向反转**      | **18 条（9%）**                                 |
| 负面占比          | 词表 **16.0%** → LLM **50.0%**（**低估 34 个百分点**） |
| 中性占比          | 词表 65% → LLM 23.5%（词表把大量抱怨当成"客观陈述"）          |

**为什么这次比上次（60.2%）更差**：这批样本集中在"业绩超预期但股价连跌"的场景，散户满屏抱怨（"连跌6天服了""九连阴垃圾""还要跌"），词表只认"跌停/大跌"这类显式词，全部漏判为中性；而"业绩""超预期""扭亏"又被判正面——**同一帖里业绩利好与情绪宣泄并存时，词表必然误判**。

### 结论：这比"样本量不足"更致命

样本少只是"结论不稳"，分类器偏差则是"结论方向性错误"。当前散户看空被低估三分之一，意味着**任何基于词表的"看空收敛"判断都不可信**。  
优先级：**LLM 标注覆盖 > 继续扩样本**。

下一步落地方式（成本极低）：有 API key 的话，2000 条标注约 ¥0.5—3，比买任何数据源都便宜；没有 key 就按每天 200 条在会话内积累。

## 十、LLM 全量标注完成（2026-10-21 00:10，DeepSeek key 已接入）

### 实测结果（2362 条语料，deepseek-chat，8 并发，3 分钟，1 条失败）

| 指标     | 词表        | LLM（DeepSeek）           |
| ------ | --------- | ----------------------- |
| 中性     | **71.1%** | **37.0%**               |
| 正面     | 15.1%     | 16.2%                   |
| **负面** | **13.8%** | **46.8%**（**+33.0pct**） |
| 方向反转   | —         | 108 条（4.6%）             |

**词表把 71% 的帖子判成中性，实际只有 37% 是中性**——大量情绪帖（"连跌6天服了""这还红不了吗""割了""太烂了"）被当成客观陈述。

### 校准后的最大变化：题材之间终于有区分度

|               | 词表                 | LLM 校准后        |
| ------------- | ------------------ | -------------- |
| 50 个题材的看空比例区间 | **8%—15%（几乎挤在一起）** | **4.3%—33.8%** |

校准后榜单才真正可用：3D摄像头 33.8%、汽车芯片 28.5%、无线耳机 27.8% 明显更悲观；光纤概念 15.2%、电网概念 16.0% 相对温和。**用词表时这些题材看起来一样悲观，无法排序。**

### 工程修复（本轮踩的两个坑）

1. **DeepSeek 推理模型陷阱**：`deepseek-flash` 的 token 先被 reasoning 消耗，`max_tokens=8` 时 content 为空 → 2163 条被静默兜底成"中性"。已改为 `max_tokens=64` + 空内容不落标注（避免假标签）+ 支持从 `reasoning_content` 提取。
2. **股吧缓存跨天失效**：缓存按抓取日命名，跨天后读不到 → 改为"读最近一份、写当日文件"，跨天复用生效（覆盖 74 → 123 只）。

### DeepSeek 网页抓取（Fetch）实测结论

- ✅ **能绕过本地 IP 封禁**：`gbapi.eastmoney.com` 本地 403，服务端抓取返回 200（说明封的是 UA/签名，不是 IP）。
- ❌ **但抓股吧列表会丢帖子标题**（Markdown 转换把表格压平，只剩阅读数/时间），不能直接做数据源。
- ❌ 雪球仍被 WAF（`CF_APP_WAF`）挡住，服务端也过不去。
- 💡 有价值的方向：它对 SPA 站点（韭研/格隆汇/同花顺圈子）可能能拿到服务端渲染内容，可作后续探索。

## 十一、两个难题的确切解决（2026-10-21 00:45）

### 问题 A：雪球 WAF —— ✅ 已解决

| 尝试                                     | 结果                                                                |
| -------------------------------------- | ----------------------------------------------------------------- |
| requests + cookie                      | ❌ 返回 `_waf_bd8ce2ce37` 挑战页                                        |
| curl_cffi 模拟 Chrome/Safari TLS         | ❌ 同样被拦（说明是 JS 挑战，不是 TLS 指纹）                                       |
| 补 `ssxmod_itna` 设备指纹 + 预热首页            | ❌ 无效                                                              |
| 老式 `arg1 → acw_sc__v2` 算法              | ❌ 页面已升级为阿里云 WAF 新版（`aliyun_waf_aa` + 混淆 JS `_0x2576duCiQ`），无 arg1 |
| DeepSeek Fetch（服务端抓）                   | ❌ 服务端同样被 WAF 挡                                                    |
| **Playwright + 本机 Chrome + 登录 cookie** | ✅ **成功**：单票 20 条真实讨论，14—15 秒/票                                    |

**实现**：`scripts/xueqiu_browser.py`；已接入扫描器 `--xq-browser N`。  
不用下载 chromium（直接 `channel="chrome"` 用系统 Chrome，省 150MB 下载）。

### 问题 B：股吧 —— ❌ 不是技术问题，是 IP 级封禁

| 尝试                         | 结果                                          |
| -------------------------- | ------------------------------------------- |
| requests / curl_cffi 换 TLS | ❌ 返回 2826 字节「身份核实」验证页                       |
| Playwright 真实浏览器（同 IP）     | ❌ 仍是验证页（56KB，含验证组件）                         |
| DeepSeek Fetch（换出口 IP）     | ⚠️ 能过（gbapi 本地 403 → 服务端 200），但**列表页丢帖子标题** |
| gbapi JSON（服务端）            | ⚠️ 200 但 `count:0`（缺签名，与 IP 无关）             |

**结论**：股吧封的是 **IP**，不是 UA/TLS/浏览器特征——**换浏览器无效，只能换 IP**。  
唯一可行三条：①等解封（实测 1—2 小时）；②代理池（¥几十—几百/月）；③接受 DeepSeek Fetch 的“无标题”限制（不推荐）。

## 十三、换模型能不能抓到更多？—— 能，但不是靠"换模型"

### 结论

**换模型本身不会增加抓取能力**。抓取靠的是厂商的工具（Search / Fetch），不是模型智力。  
真正有用的是：**不同厂商 = 不同出口 IP**，能分摊 IP 级封禁；而各家工具的解析质量不同。

### 但由此发现了一条真正的突破口：DeepSeek Search

`POST https://api.deepseek.com/v1/tools/search`　`{"query": "site:guba.eastmoney.com 300750", "count": 50}`

**返回的是股吧帖子列表本身**（不是链接集合）：

| 字段                | 内容                                |
| ----------------- | --------------------------------- |
| title             | **完整帖子标题**（`宁德时代回应市场对新能源行业需求担忧…`） |
| date              | 精确日期（2026-10-20）                  |
| url               | 帖子详情链接                            |
| snippet / summary | 摘要（可用于语义分类）                       |

**实测覆盖（宁德时代，4 个 query）**：去重 **176 条**，其中 10-20 当天 57 条、10-19 有 21 条——  
**比股吧列表页一页的 60 条还多**，且走 DeepSeek 服务器，**完全不受本地 IP 封禁影响**。

### 已接入的三级股吧通道
