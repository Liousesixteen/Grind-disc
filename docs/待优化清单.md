## B-01 主题簇 + 跨链新簇（2026-10-26 标记，暂缓）

**现状**
- `scripts/theme_tree_chain.py`：链内社区发现 → `theme_cluster`（36 个）
- `scripts/theme_cross.py`：跨链社区发现 → `theme_cross_cluster`（33 个结构簇）+ `theme_cross_stock`（1 万条股票边）
- 看板「⑦ 库数据」→ 跨链新簇（加速榜）：结构层离线、打分层 15 秒实时

**已知问题**
1. **参数未定标**：簇数随阈值剧烈变化（2 / 17 / 30 / 31 / 45），当前阈值（共现≥6、J≥0.2、成员≥3）是拍的，没有回测依据
2. **簇名不可读**：自动取名 `链·最大概念`（如"消费链·跨境电商"），不是人能直接理解的题材名
3. **噪声未清净**：仍混入"兰州西宁城市群""美国食品公司"这类地域/海外名（BAD 正则挡不全）
4. **结构不随时间演化**：簇结构每日重算但前后不连续（簇 ID 重排），无法追踪"某个簇在延续/消亡"
5. **未验证有效性**：簇内涨停票的**次日溢价**没测，不知道这个信号是否真有钱赚
6. **未接自动任务**：`theme_cross.py` 没进 `daily_run.sh`，明日起不会自动重算
7. **无历史快照**：只存最新一版，无法回看"上周这个簇是什么样"

**优化方向（按优先级）**
1. **回测验证**（最重要）：簇内涨停票 T+1 溢价 vs 全市场涨停溢价，若显著更高才算有效信号
2. **簇 ID 稳定化**：用"成员概念集合的指纹"（如排序后哈希）做 ID，保证同一簇跨日可追踪
3. **结构演化追踪**：新增 `theme_cluster_history(date, cluster_id, ...)`，每日快照，可看新增/消失/合并
4. **参数定标**：用过去 60 天数据做网格搜索，选"次日溢价最高"的参数组合，而不是拍
5. **簇名人工校正**：给 33 个簇起可读名字，存 `theme_cluster_alias`
6. **接入 daily_run.sh**：收盘后自动重算结构
7. **噪声正则补全**：把 THS 里的地域/海外/风格名彻底过滤（当前 BAD 正则仍有漏网）

**验收标准**
- 回测显示簇内涨停 T+1 溢价 > 市场均值，且样本 ≥ 200 次
- 同一簇可跨日追踪（ID 稳定率 > 80%）
- 簇名人工可读率 100%

**依赖**
- 回测需要：`fact_snapshot` 已有 250 天（够）；次日溢价 = T+1 收盘 / T 日收盘
- 结构演化需要：每日增量跑一次（接 daily_run.sh）
