# 大盘日报 SOP（一句话触发 → 固定模板出稿）

> 制定：2026-10-21｜适用：A 股大盘分析日报
> 触发语：**「分析一下今天的大盘」**（及其同义变体：分析下大盘 / 今天大盘怎么样 / 帮我复盘今天）
> 模板：`templates/大盘熔炼定位.html`　生成器：`scripts/report_gen.py`
> 样板：`reports/2026-10-20/大盘熔炼定位-20261020.html`（**结构、篇幅、语气以它为准**）

---

## 一、这条 SOP 解决什么问题

以前每次都要从零组装，导致：
- **漏节**（3.5 日内钟整节缺席）
- **手抄错**（收盘价抄成盘中值、最高价少记 8 点）
- **偷懒用代理**（证券用非银代替）
- **工序缺失冒充数据缺失**（辈分校验写"缺数据"）

现在固定为：**读数交给脚本，判断由我写，结构由模板锁死。**

---

## 二、七步流程

### 步骤 0 · 判断时点（10 秒）

| 情形 | 处理 |
|---|---|
| 非交易日 | 不出日报；只出「休市说明 ＋ 下一交易日预案」 |
| 交易日 **15:40 之前** | 出「**盘中快照**」版，标题标注时点，**不使用收盘口径**；不写"今日收盘" |
| 交易日 **15:40 之后** | 出**正式收盘版**（正常情况） |

> ⚠ 铁律：收盘数据必须等结算。15:10 取到的仍可能是过渡值（2026-10-20 实测上证 3732.43 → 结算后 3735.37）。**新浪时间戳 ≥15:30 才采信**。

### 步骤 1 · 一条命令取齐读数

```bash
# 有宏观输入时（推荐）：
.venv/bin/python scripts/report_gen.py --date YYYYMMDD --macro cache/macro/YYYYMMDD.json
# 没有宏观输入时：
.venv/bin/python scripts/report_gen.py --date YYYYMMDD
```

产出 `reports/<日期>/大盘熔炼定位-<日期>-模板生成.html`（**草稿名，不覆盖已交付稿**）。

自动填好的读数块：
- KPI 四卡（上证收盘/高/低/额、两市额、个股上涨占比、涨停结构）
- 3.10 指数表（上证50/沪深300/中证500/中证1000/国证2000/北证50/科创50/创业板指/证券 399975/证券龙头 399437）
- 3.10①b 属性轴（科创50 vs 创业板指 ＋ 各自板块内涨股比 ＋ 背离提示）
- 3.10⑤ 波段层级（本波/前波/父浪 ＋ 倍数律 ＋ 辈分校验）
- 情绪池（涨停/炸板/跌停、连板分布、涨停行业分布）
- 板块双口径榜（行业 31 ＋ 概念 805，各出「涨幅榜前 10 × 资金榜前 10」）
- 股池块（数据日/快照数/池层三档/焦点榜前十，**含滞后交易日告警**）
- 基本面钟四周期表（需 `--macro`，**PPI 105.0 自动换算为 +5.0%**）
- 附录A 19 项骨架、附录B 来源表

### 步骤 2 · 补脚本拿不到的三块（约 5 分钟）

| 缺什么 | 现状 | 怎么补 |
|---|---|---|
| **股池**（数据日/池层/焦点榜） | **已自动**（读 `cache/pool_*/summary.json`，**自动算滞后天数并告警**） | 无需人工 |
| **基本面钟** | **半自动**：脚本只吃标准输入，不取数（MCP 无法在脚本内调用） | 用宏观库取数 → 按 `templates/macro_input.example.json` 落盘 → `--macro` 传入；**PPI 按「上年=100」自动换算** |
| **消息与催化** | **纯人工** | 资讯检索 `mx_finance_search_news`；文本判断无法脚本化 |

> 三块都必须带 **asof 日期 ＋ 来源**；取不到写「缺（原因）」，**不许留空、不许估算**。

### 步骤 3 · 填判断块（核心工作，27 个黄框）

按顺序填，每个黄框里都写清了"该写什么"：

1. `一句话结论`——2—4 句，落到「相位＋主线＋双通道＋仓位」四者
2. `1.1 相位`——判定链＋为何不能升级
3. `1.3 3.10 判断位`——①哑铃/橄榄、②强弱共振、⑧钝化、⑫3 浪否定
4. `1.4 ②情绪钟 / ③环境系数查表 / ④吸血三项 / ⑤风险预算`
5. `2.3 连续性 / 2.4 主线判定 / 2.5 四问 / 2.6 梯队 / 2.7 支线 / 2.8 演化链`
6. `层3 双通道 ＋ 互检`
7. `层4 仓位方程三层取小 ＋ 防守线 ＋ 若持仓`
8. `层5 复盘（上一日判断逐条验证）＋ 次日预案（2—3 条二值）`
9. `风险与失效条件`（3—5 条 ＋ 失效条件）

> **判断块不自动化**——它们是判断，不是计算。自动生成只会得到"看起来严谨"的空话。

### 步骤 4 · 附录A 打勾（19 项）

逐项标：`✓ 过` / `◐ 部分` / `✗ 未过` / `未用（原因）` / `缺数据（原因）`。
**不允许整节跳过**；跳过必须写明原因。

### 步骤 5 · 校验（三道）

```bash
.venv/bin/python scripts/check_refs.py                    # 引用三件套：要 0 ERROR / 0 WARN
.venv/bin/python scripts/report_gen.py --date YYYYMMDD --strict   # 有未填判断块则非零退出
```

外加人工三项：
- **标签平衡**（table/tr/td/div/p 开关数相等）
- **数值指纹**（收盘价、最高/最低、关键位与当日实际一致）
- **口径声明**（时点、来源、缺口是否写全）

### 步骤 6 · 转正式名并交付

```bash
.venv/bin/python scripts/report_gen.py --date YYYYMMDD --write-canonical --force
# 或手工：把 -模板生成.html 复制为正式名（推荐——正式稿由人工定稿后另存，不重跑）
```

交付时用 `present_files` 打开，并在对话里给 200—300 字摘要 ＋ 文件路径 ＋ 免责声明。

## 三、质量闸门（任一不满足 → 不出稿）

1. **收盘口径**：数据时点 ≥15:30 结算后；盘中版必须标注"盘中快照"。
2. **判断块清零**：`--strict` 必须通过（0 个黄框）。
3. **附录A 满格**：19 项全部有状态，无空白。
4. **缺口显式**：所有"取不到"都写了原因，**没有静默删行**（熔炼系统 3.9 五条数据铁律 第①条）。
5. **证据等级**：每个主要结论标 A/B/C/D。
6. **免责声明**：原文一字不改。

## 四、常见故障与处置

| 故障 | 处置 |
|---|---|
| 东财 push2his 整站限流（`RemoteDisconnected`） | 换新浪/腾讯；仍不行则标「缺数据（接口限流）」并降级 |
| 宏观库返回宽表且截断 | 只取所需月份的少量指标；不整段拉 |
| 板块榜数字与盘中不同 | 正常（收盘后刷新）；**必须记 asof 时点**，不混用盘中/收盘 |
| 涨停池取不到 | 标「缺数据」；**不用户数估算** |
| 生成器拒绝覆盖 | 正常保护。要覆盖加 `--force`（自动备份到 `.workbuddy/backups/reports/`） |

## 五、边界（写清楚，免得越界）

- **只产研究结论，不产交易指令**：报告里不出现"因此买入/卖出/加仓 X 成"。
- **不替用户过层0 门禁**：睡眠/身体/情绪/环境四问只能用户自己填。
- **不承诺收益、不预测点位**。
- **不修改体系文件**：本 SOP 只调用 `熔炼系统`（判断口径）与 `作业节奏`（结构与时点），不改它们。
