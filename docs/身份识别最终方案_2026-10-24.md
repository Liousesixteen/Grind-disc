# 个股身份识别 · 最终方案

> 版本 v1.1 ｜ 2026-10-24 ｜ 基于对 1036 只票画像缓存、3697 条主营项名、749 个环节词的实测
> 结论先行：**规则做到了「可复现的准确」，没有做到「无所不能」。最终落点是
> 「规则算 502 只 + 行业推 507 只 + 人工核 27 只」，LLM 层完整设计但一次都没用上——
> 因为攻击面被规则压到 30 只，人工逐票判断更准。**
> 关键关系仍是「LLM 造词表，规则做执行」：LLM 取代的从来不是规则，是**靠字长猜语义**。

## 一、规则到底准不准（实测，不是估计）

### 1.1 身份来源分布（1036 只，2026-10-24 Step2 后半收尾后）

| 来源 | 只数 | 占比 | 性质 |
|---|---|---|---|
| 主营项名算出来（F10 按产品/按行业） | 502 | 48.5% | **算的** |
| 申万行业兜底 | 507 | 48.9% | **推的**（以前三级名大面积缺失，现在 100% 完整） |
| 逐票人工核实 `identity_override.json` | 27 | 2.6% | **核过的**（其中 12 只确认「19 链覆盖不到」） |
| 经营范围兜底 | 0 | 0% | ~~猜的~~（地域 bug 修好后，这条路径不再触发） |

**"一半是推的"这个结构没变——变的是"推得准不准"。** 起初那版申万行业兜底有三个
静默 bug：64 只票的行业标签整个是空的、9 只没有地域锚点、还有 `商贸社服链` 这种
不存在的链。现在这三处都修了，行业标签 59 只「空→有」、15 只「补全一级行业」、丢失 0，
并且删掉了 7 条把几百只票塞进一个窄环节的错映射。

### 1.2 词表对业务语料的覆盖率

- 主营项名语料 **3741 条 / 3036 种写法**
- 能被 716 个环节词命中的：**1652 条（44.2%）**
- 命中不了的：**2089 条（55.8%）**

未命中 Top：`其他` 268 次、`其他主营业务` 47、`其他产品` 31、`技术服务` 18、`其他业务` 16、`配件及其他` 8、`销售商品` 7、`解决方案` 3、`版权运营` 3 …

**3036 种写法，716 个词，天生覆盖不了。** 这不是"再补几个词"能解决的，是词表这种方法的容量上限。

### 1.3 三个**结构性**缺陷（不是偶发错误）

#### 缺陷 A：18 个环节歧义词，归属由 JSON 书写顺序决定

同一个词出现在 ≥2 个不同环节里（实测 18 个）：

| 歧义词 | 冲突的环节 |
|---|---|
| 硅料 | 光储风·光伏 / 半导体·材料 |
| 北斗 | AI算力·运营与卫星 / 军工·军工电子 |
| 系统集成 | 软件·行业IT / 机器人·应用集成 |
| 激光雷达 | 新能源车·智能化 / 机器人·感知 |
| 云计算 / 边缘计算 | AI算力·算力服务 / 软件·云与SaaS |
| 医美 | 医药·医美 / 消费·化妆品医美 |
| 养殖 / 水产 / 种业 / 饲料 | 农业 / 消费·预制菜养殖 |
| 服装 / 家纺 / 纺织 / 鞋帽 | 消费·服装家纺 / 轻工纺服 |
| 玩具 / 潮玩 | 传媒·IP与潮玩 / 消费·宠物婴童潮玩 / 轻工·文娱用品 |
| 农药 | 农业·农化 / 资源·化工 |

**暴露面：37 只票（占主营票 7.1%）** 的归属完全取决于 `pool_config.json` 里谁先写。
实测样本：`600345 长江通信` 项名含「系统集成」→ 归到 `软件·行业IT`；如果配置换个顺序，它就变成 `机器人·应用集成`。**同一份数据，两次运行可能给出不同答案。**

#### 缺陷 B：词长 ≠ 具体度

实测 df>25 的环节词有 **15 个，全部是二字词**：

| 词 | df | 所属环节 | 处理 |
|---|---|---|---|
| 设备 | 110 | 半导体·设备 | 本就不参与环节判断（GENERIC_KW） |
| 材料 | 103 | 半导体·材料 | 同上 |
| 工程 | 65 | 地产基建·建筑施工 | **加共现门槛** |
| 租赁 | 54 | 金融·多元金融 | **加共现门槛（反向排）** |
| 制造 | 44 | 半导体·制造 | 本就不参与环节判断 |
| 软件 | 41 | 软件·行业IT | 放行（逐条核过，语义准确） |
| 电力 | 38 | 公用事业·火电水电 | **加共现门槛** |
| 电池 | 33 | 新能源车·链级 | 链级词，只定链 |
| 医药 | 33 | 医药·链级 | 链级词，只定链 |
| 芯片 | 28 | 半导体·链级 | 链级词，只定链 |
| 设计 | 27 | 半导体·设计 | 本就不参与环节判断 |

| 医疗 | 26 | 医药·链级 | 链级词，只定链 |

**重要修正（Step1 实测）**：初稿这里写「8 个泛词」，是因为当时把 `df` 算成了**不同写法数**；
正确口径是**命中的票数**。按票数算是 15 个，但其中 10 个其实没问题——真正需要门槛的只有 5 个
（工程/租赁/电力/商业/食品），这个区分很关键：一刀切给 15 个词都加门槛，会把「软件」「营销」
这两个语义完全收敛的词也废掉。

词长与扩散度的实测曲线（越短越泛，df 按票数）：

```
len=1  9 词   平均 df 6.1   最大 23
len=2  292 词 平均 df 4.5   最大 110   ← 泛词全在这层
len=3  139 词 平均 df 1.5   最大 21
len=4  223 词 平均 df 0.8   最大 9
len=5  34 词  平均 df 0.5   最大 4
len≥6  19 词  平均 df <0.4
```

**"最长词优先"只在"长词存在且正确"时成立。** 当项名叫「自动化设备工程」时，`工程`(2) 和 `设备`(2) 一样长 → 退化成书写顺序；当项名叫「智能控制设备」时，`设备` 赢了，`控制` 也赢不了它。埃斯顿那次就是 `智能制造`(4) 压过 `机器人`(3)——长度赢了，语义输了。

#### 缺陷 C：长度无法代替词表准入

`智能制造` len=4、df=4，压死了 `机器人` len=3、df=14。**这四个字看着很具体，实际只服务 4 家公司。** 判断一个词该不该独立成条，看的是 df（扩散度）不是字数。现在配置里没有任何准入标准，全凭手感。

### 1.4 唯一的好消息

主营项名一旦命中，**91.7%（477/520）能继续下钻到环节**，不是只停在链级。所以瓶颈在"命中"，不在"下钻"——把命中率从 50% 抬到 75%，身份粒度会自动跟着上去。

## 二、LLM 到底准不准

### 2.1 它能做的（规则永远做不到的）

| 项名 | 规则结果 | LLM 能做 |
|---|---|---|
| `MCD不一样的分销` | 命中不了 | 判为医药·流通 |
| `智能控制业务` | 只能靠 `控制` 蹭到机器人 | 判为机器人·控制 |
| `其他`（268 次） | 命中不了，靠行业兜底 | 结合行业+经营范围判 |
| `技术服务`（18 次） | 命中不了 | 结合上下文判 |

**它解决的是"项名 → 环节"这一步的语义问题，不是"打标签"，这正是规则的天花板。**

### 2.2 它不能碰的两条红线

**红线一：不能在线跑（不可复现）。** 同一批数据跑两次可能给两个答案，而看板要跨日对比、归因要能回测。**必须离线批跑一次 → 结论落盘成文件 → 运行时零调用。**

**红线二：不能进动态归因。** 五因子打分（`0.42×超额 + 0.18×涨停率 + …`）是纯数值计算，任何不可复现的环节混进去，整个回测体系作废。LLM 只能进静态身份层，不能进今天的"为什么涨"。

### 2.3 它还有第三个坑：看起来很有道理

LLM 最危险的不是答错，是**答错时语气和答对时一样自信**——和大智慧那次"一个数据缺失被包装成一个结论"是同一类错误。所以必须：

- **强制枚举**：只允许从 19 链 / 109 环节里选，不许自创
- **必须给置信度和依据**：说不出依据的打回
- **低置信不采纳**：宁可留 `≈`，不许硬填

## 三、最终方案：三层架构

```
┌─────────────────────────────────────────────────────────┐
│ 第 1 层  规则层（日常执行）                                │
│   显式优先序 + df 准入门槛 + 自检脚本                      │
│   · 可复现 · 毫秒级 · 每天跑                              │
│   目标：不猜 → 猜了要标 ≈                                │
└───────────────────────┬─────────────────────────────────┘
                        ↓  规则答不了的（实测最终只剩 30 只，不是 558 只）
┌───────────────────────┴─────────────────────────────────┐
│ 第 2 层  人工核实 override（27 条，走的就是这一层）        │
│   只处理：规则明确答错的 + 19 链确实没有对应环节的         │
│   产出：identity_override.json（带 reason/by/conf/asof）   │
│   · 强制枚举 19×108 · con<0.7 不采纳 · 纳进自检校验       │
│   · LLM 通道已就绪但本轮未启用（30 只不值得上流水线）      │
└───────────────────────┬─────────────────────────────────┘
                        ↓
┌───────────────────────┴─────────────────────────────────┐
│ 第 3 层  仲裁层（人工，量小）                             │
│   一致     → 采信                                        │
│   不一致   → 进人工队列（分歧＝词表缺陷的信号）             │
│   都答不了 → 保留 ≈，不硬填                              │
└─────────────────────────────────────────────────────────┘
```

**关键设计：override 与词表分离。**
- `pool_config.json` 存的是**规则**（一类词怎么判）
- `identity_override.json` 存的是**答案**（这一只票怎么判）
- override 优先级最高，但必须带 `reason` 和 `by`（谁定的、凭什么），可随时审计。**不许把个案硬编码进词表**——那会把词表污染成一张查表。

## 四、三步落地

### Step 1｜纯规则修复（不依赖 LLM）——✅ 已完成 2026-10-24 17:5x

| 动作 | 具体做法 | 结果 |
|---|---|---|
| ① 18 个歧义词显式绑定 | `chains._归属绑定`，查表优先于最长词 | **18/18 全部绑定**，跑两遍结果一致 |
| ② 泛词加共现门槛 | df>25 的词必须与限定词共现 | 15 个泛词里 **5 个加门槛**（工程/租赁/电力/商业/食品），4 个本就不参与环节判断，4 个是链级词，2 个逐条核过后放行 |
| ③ 自检脚本 `audit_config.py` | 只读，**五张表**（A 歧义 / B 泛词 / C 倒挂 / D 孤儿 / E 题材层归位） | 红框 0、黄框 0、`--strict` 退出 0 |
| ④ 准入标准写进 README | df 门槛 + 泛词不进 match + 改完必跑自检 | 已成文 |

**Step 1 实测结果（全量 1036 只 + 535 个题材）**

| | 变化 | 性质 |
|---|---|---|
| 个股身份 | **37 只** | 全部为修复或改进，无退化 |
| 题材归属 | **28 个** | 13 个从"未归"变有归属，5 个从错链变对链 |
| 可复现性 | 抽 400 只跑两遍 | **0 不一致**（原来 18 个词随书写顺序漂移） |
| 环节数 | 109 → **108** | 删掉 消费链·服装家纺（4 词全部与轻工纺服链重复登记） |

**过程中被 diff 抓出来的 5 个坑（都已修）**

1. **`bind_ok` 在链级判断时拿 `"AI算力链·"` 比 `"AI算力链·算力服务"`，永远不等**
   → 所有绑定词在 `chain_of` 里被整条链跳过 → `chain_of('云计算')` 返回空，**盘中归因全废**。
   修：链级判断只比链名。
2. **绑定的目标链必须在链级 `match` 里有这个词**
   → `激光雷达` 绑到新能源车链，但该链 match 无此词 → 两条路都堵 → 掉给军工链的「雷达」。
3. **白名单门槛会误伤正主**：`租赁` 用"必须含"把「德润租赁」（新力金融 70% 主业）挡掉了。
   改成"除非含"黑名单才对。
4. **门槛不认分部口径后缀**：`电力板块`（大唐发电 94.3% 主业）被挡，退回链级。
   修：项名 = 该词 + 「板块/业务」时放行。
5. **门禁修复会连带弄坏相邻票**：`工程` 加门槛救回 6 只（研发工程/数智工程/工程塑料），
   但同时把「电力工程建设」也挡了。补 `工程建设` 到白名单才两全。

**教训**：改词表**必须跑全量 diff 并逐只看**。这 5 个坑里没有一个是能靠"想一想"发现的，
全部是 diff 出来的——而且如果不逐只看，第 1 个坑（归因全废）会被当成"没问题"直接上线。

### Step 2｜补漏 —— ✅ 全程未用 LLM，规则 + 27 条人工（2026-10-24 完成）

**关键判断：先别上 LLM。** Step 1 后仍有 326 只缺环节，但拆开看：**270 只是「行业名认不出环节」**，
真正的主营项名/经营范围长尾只有 56 只。而三级行业名只有 **105 种**——判断 105 个名字，比逐票判断
326 只便宜两个数量级，且永久有效、可复现、可审计。

规则做完后攻击面从 558 只缩到 30 只，这时候再评估「要不要上 LLM」，答案是**不要**：
30 只逐票人工判断比搭一条 LLM 流水线更准、更便宜、更可审计。
**LLM 层的入口仍然留着，但到目前为止一次都没用上——这本身是结论，不是遗憾。**

#### 前半：`chains._行业定环节`（纯规则）

- 表覆盖申万三级名 + 二级名，`main_seg` 按 三级→二级→一级 查，命中即用
- 剥罗马数字后缀（`IT服务Ⅲ` → `IT服务`），否则这 19 只全查不到
- **二级/一级名不许用来猜环节**（踩过：食品饮料→啤酒饮料 15 只、纺织服饰→纺织制造 13 只、
  传媒→数字媒体 11 只，全是错的）；粗一级的行业名只定链，环节宁可留空
- **主营只定到链时借行业表补环节**（链必须一致）：33 只汽车零部件、16 只软件开发、10 只半导体卡在这

#### 后半：修 3 个静默 bug + 审查表 + 27 条 override

| 修的什么 | 影响 | 效果 |
|---|---|---|
| 地域锚点只认「…板块」，内蒙古/黑龙江不写「板块」 | 64 只票行业标签全空，且一级行业名+地域名被当题材打分 | 行业标签 59 只空→有、15 只补全一级、**丢失 0** |
| 9 只科创板/次新/大市值既无板块也无地域 | 百济神州、中国移动、中芯国际 | 用申万一级名验证后取前 3 词 |
| `IND2CHAIN` 指向不存在的「商贸社服链」 | 所有靠行业兜底的零售/社服票 | 改消费链 + 加存在性检查 |
| `_行业定环节` 有 24 条错配 | 专用设备/自动化设备/其他专用设备/其他自动化设备→机器人本体（全市场 262 只）、制冷空调设备、能源及重型设备、纺织服装设备、楼宇设备、轨交设备、机床工具、其他电子、其他计算机设备、其他电源设备… | 删除，`_行业定环节` 183 → 159 条；保留的必须「与环节同名或语义等价」 |

| 指标 | Step1 后 | Step2 前半 | **Step2 后半（当前）** |
|---|---|---|---|
| 有环节 | 709（68.4%） | 1006（97.1%）⚠️含水 | **933（90.1%）** |
| 有链无环节 | — | — | 91（8.8%） |

**⚠️ 97.1% 是注过水的，这一节最重要。** 有环节从 1020 掉到 933，少掉的 **87 只**
全部是被删掉的 24 条映射搬进去的——主力是
`专用设备/自动化设备/其他专用设备/其他自动化设备/能源及重型设备/纺织服装设备/
楼宇设备/轨交设备/机床工具 → 机器人链·本体` 这一串：注塑机、色选机、针织横机、
电梯、轨道交通信号全都成了"机器人本体"，`机器人链·本体` 一度有 25+ 只。

把这些映射删掉后 **`机器人链·本体` 只剩 3 只，全部是真机器人整机
（688836 / 002747 埃斯顿 / 300607 拓斯达）**。

覆盖率从 97.1% 到 90.1% 不是退步——**是账算清了**。留下 91 只"链对了、环节没有对应"
比挂着 87 个假环节诚实得多。

**`identity_override.json`（27 条）**：15 只补环节（多氟多→电池、同飞股份→数据中心、
亚玛顿→光伏、味知香→预制菜…），12 只确认「19 链覆盖不到」（工业制冷、第三方检测、
煤机、电动推杆）。后者写空串 + reason，前端显示「未归链（已核实）」而不是空白——
**「体系覆盖不到」是个答案，不是失败。**

## 五、为什么不推荐"全量 LLM"

| | 全量 LLM | 本方案（规则 + 27 条人工） |
|---|---|---|
| 每天调用 | 1036 次 × N | 0 次 |
| 可复现 | 否 | 是（规则 + 落盘的 override） |
| 回测 | 废掉 | 不受影响 |
| 出错定位 | 分不清是词表还是模型 | 规则错了查词表，override 错了查那一条 |
| 实际攻击面 | 1036 只 | 规则压完后 **30 只**，人工逐票判断 |

**"最长词优先"不会因为有了 LLM 而消失**——它只是从"决定 1036 只票归属的主算法"降级为"在 override 和补充词表之外的最后一道兜底"。真正被替换掉的不是某条规则，是**靠字长猜语义**这件事。

**这一轮最值钱的产出不是覆盖率，是三个静默 bug。** 它们不报错、不抛异常，
只是在 64 只票上给出错答案，而且看起来和正确答案一模一样：
地域锚点只认「…板块」、`IND2CHAIN` 指向不存在的链、二级行业名被塞进窄环节。
**覆盖率从 97.1% 到 98.5% 只多了 14 只，但被纠正的错答案有 90 多个。**
