## 二、19 链 / 110 环节到底怎么做（四层）

### 第 1 层：字典（定义，静态）

- **链（19）**：`dim_chain` —— 每条链有 `match` 词表（共 400 词），用来把概念/题材归到链；
- **环节（110）**：`dim_segment` —— `seg_id = 链·环节`（如 `机器人链·本体`）；
- **环节词（758 去重）**：`segment_word` —— 每个环节的判定词（减速器、丝杠、灵巧手…）；
- **三个守门规则**：
  - `chain_binding(18)`：跨环节重复词指定唯一主口径（"传感器"算机器人·感知还是车·智能化）；
  - `chain_cooccur(7)`：泛词（工程/电力/商业/食品/租赁/饲料/轨道交通）必须与特定词共现才算；
  - `industry_chain(48)`：申万行业兜底（半导体→半导体链），但**一级行业不得单独定链**。

### 第 2 层：归属（两条独立的路，绝不混）

| 路径 | 输入 | 判定 | 落点 |
|---|---|---|---|
| **主业路** | F10 主营项名（占营收 ≥max(20%, 最大项×85%)） | 环节词匹配（最长词优先） | `dim_stock.biz_chain / biz_seg` |
| **题材路** | 个股全部概念 → 概念归位 | 链词/环节词匹配（concept_map 已算好） | `dim_concept.chain_id / seg_id` |

**为什么分开**：主业回答"它靠什么赚钱"（静态、唯一），题材回答"今天资金当它是什么"（动态、多对多）。
两者不一致时，差值就是看板上的**错位度**（主业驱动 / 链内外溢 / 跨链蹭概念）。

### 第 3 层：关系（多对多，统一边表）

`rel_edge` 一行一条边，四类：

| rel_type | 例 | role | weight |
|---|---|---|---|
| `stock_concept` | 603280 → 机器人概念 | 有效概念 / 噪声标签 | — |
| `stock_chain` | 603280 → 地产基建链 | **主业** | 1.0 |
| `stock_chain` | 603280 → 公用事业链 | 题材 | 5.0（命中概念数） |
| `stock_segment` | 603280 → 地产基建链·工程机械 | **主业** | 1.0 |
| `concept_chain` / `concept_segment` | 机器人概念 → 机器人链·本体 | — | — |

南方路机实测：**9 条票→链边**（1 主业 + 8 题材），这就是"一只票同时属于多条链"的真身。

### 第 4 层：视图（展示用的"唯一"）

```sql
SELECT * FROM v_stock_primary WHERE code='603280';
-- ('603280','地产基建链','地产基建链·工程机械','主业',1.0)
```

- 主业存在 → 用主业；
- 无主业 → 取题材命中数最多的链，环节取该链下权重最高的环节；
- **5,517 只有坐标，59 只无坐标**（既无 F10 主业、概念也归不上产业——如实留空，不硬塞）。

### 两种口径必须分清

| 口径 | 用途 | 南方路机 | 机器人链·本体 |
|---|---|---|---|
| **主坐标（v_stock_primary）** | 分组/家数/梯队可加总 | 地产基建链·工程机械 | 145 只（主坐标） |
| **多对多（rel_edge 全量）** | 查"谁和这个环节有关" | 9 条链边 | **1,347 只**（概念命中） |

差额就是"蹭概念"的部分——这正是错位度的价值。

## 三、怎么用（三条示例 SQL）

```sql
-- 1) 一只票的全部身份（含所有链、所有概念、涨停与归因）
SELECT s.*, v.chain_id, v.seg_id FROM dim_stock s
LEFT JOIN v_stock_primary v ON v.code=s.code WHERE s.code='603280';

-- 2) 某环节的票（多对多）与主坐标票（可加总）
SELECT COUNT(DISTINCT src_id) FROM rel_edge
 WHERE rel_type='stock_segment' AND dst_id='机器人链·本体';
SELECT COUNT(*) FROM v_stock_primary WHERE seg_id='机器人链·本体';

-- 3) 今日涨停票 + 主归属 + 归因 + 错位度
SELECT f.name,f.lb,f.main_theme,f.attr_theme,f.attr_score,f.layer
FROM fact_limitup f ORDER BY f.score DESC LIMIT 20;
```

## 五、运行与维护

```bash
.venv/bin/python scripts/kb_build.py --rebuild   # 重建（自动备份旧库）
.venv/bin/python scripts/kb_build.py --verify    # 只校验（表行数 + 抽查）
```

- 库文件可随时拷走（单文件）；WAL 模式下备份用 `sqlite3 .backup`；
- 重建是幂等的（`INSERT OR REPLACE`），但 P1 阶段仍用 `--rebuild` 保证干净；
- **建库不联网**，只读本地缓存——所以在服务器上可直接跑。

## 八、L3 候选审核结论（2026-10-25 22:40）

- 249 个候选**全部**是「已映射到现有环节的产品名」（如 算力服务→AI算力链·算力服务、光模块→AI算力链·光互联），**没有带来新语义**；

- **结论：L3 保持 110 环节，0 新增**。要扩展到 250–400，只能依赖外部产业链定义（同花顺/深交所），当前被 JS 挑战阻断。
