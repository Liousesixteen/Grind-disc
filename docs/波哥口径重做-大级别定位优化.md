## 二、一个必须纠正的算法误读（影响 364 点）

> **术语正名（2026-10-24）**：波哥口语的「0.618 位」，按标准叫法是「**0.382 回撤位**」——同一位置，只是从两头量（起点往上 61.8% ≡ 高点回撤 38.2%）。
> **标准「0.618 回撤位」是另一个点**（更深），两者差 180—380 点。

**验证**（用他 10-23 的原文数据反推，大 31 浪 2635→4258）：

| 项 | 算法 | 结果 | 他说的 |
|---|---|---|---|
| 半分位 | (2635+4258)/2 | **3446.5** | 3447 ✔ |
| 0.382 回撤位（他的「0.618 位」） | 4258 − 1623×0.382 | **3638.0** | — |
| 标准 0.618 回撤位 | 4258 − 1623×0.618 | **3255.0** | **不同点，差 383 点** |
| 两者中间 | (3446.5+3638.0)/2 | **3542.3** | 「目测 3543」 ✔ |

**如果按常规「回撤 61.8%」算，目标会是 3254 而不是 3638——差 384 点。** 这个误读足以把"跌够了"判成"还差很远"。

### 3.2 级别判定：这轮调整升了两级

| 级别 | 当前段 | 上一同向段 | 时间比 | 判定 |
|---|---|---|---|---|

**关键结论**：
- **mid 级（中级别）的下跌 109 日 vs 上一同向 15 日 = 7.27×，升两级** → 这不是普通回调，是**大级别调整**

→ 与旧版结论一致（"中级别调整已确立、大级别上涨未破"），但**依据从"价格幅度"换成了"时间比"，更贴他自己的口径**。

## 四、由此得到的判断（比旧版精确）

旧版说法：**「止跌，不是启动」**。

1. **位置已到**：半分位 3472 / 0.382 回撤位 3654 / 中枢 3563 / 等幅 3658——**四套算法同区间，今日低点 3574 落在带内**（更深的 0.618 回撤位 3290.61 未到）。
2. **级别已确认够大**：mid 级时间比 7.27×（升两级）→ 这是大级别调整，不是小回调。
3. **但启动信号未出**：底部钝化**未磨掉**（DIF 差 5.04）→ 按他自己的规则，**此刻的反弹仍应按「下跌中继」对待，不能定性为反转**。

## 六、诚实标注：哪些是自动的，哪些还得人做

| 环节 | 自动化程度 |
|---|---|
| 分段（ATR） | ✅ 全自动 |
| 时间 2 倍律 | ✅ 全自动 |
| 半分位 / 0.382 回撤位 / 0.618 回撤位 / 等幅 | ✅ 全自动 |
| 钝化状态（DIF vs 前低） | ✅ 全自动 |
| **"这是长 3 浪还是大 31 浪"（选定参照段）** | ❌ **靠人判断**——我用"取日期最近的参照级别低点"代理，可能选错 |
| **微浪型划分点（0.01 点硬判）** | ❌ 无法自动，他的划分点靠人眼选 |
| **交替原则** | ⚠ 可半自动（判断相邻段的长短关系），但"该不该交替"需判断 |

**所以本工具的输出是「在假定参照段正确的前提下」的推算。参照段一变，目标位全变。** 这一点必须每次标注。

### 9.4 脚本已修正

`boge_regime.py` 新增 `--ref-high`（手动指定反弹参照高点）。**为什么需要手动**：波哥选 3995.18（而不是 5-13 的 4242 或 9-22 的 3952）靠的是判断「**本轮下跌从哪开始**」——这属于人眼判断，自动选取会取错（取到 4242 或 3952）。

### 9.5 两套斐波那契的正确用法（并存，不互斥）

| | 回撤位（支撑） | 反弹位（阻力） |
|---|---|---|
| 用途 | 判「跌够没」 | 判「弹到哪」 |
| 何时用 | 调整进行中 | **止跌迹象出现后** |
| 起止 | 大级别高点→低点 | **本段低点→前高** |
| 当前状态 | 半分位 3472 / 0.382 位 3654 / 0.618 位 3290 | 0.191 已过，**0.382 位 3735 是下一阻力** |

> **流程**：先用回撤位判「调整够不够」→ 再用见底迹象判「止跌没」→ **止跌确认后切换到反弹位**算「能弹到哪」。此前我的脚本缺第三步。
