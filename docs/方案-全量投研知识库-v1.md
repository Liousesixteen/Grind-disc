# 全量投研知识库方案 v1（2026-10-25）
## ——「库穷尽一切，板只呈现最强」

> 状态：**方案，未实施**。目标不是"再加几张表"，而是把现有的 JSON/CSV 拼装升级为
> **可查询的实体-关系库（SQLite）＋ 可推理的图（networkx）＋ 每日事实层**，
> 看板退化为它的一个"Top-N 实时视图"。

---

## 〇、需求拆解（三层，缺一不可）

| 层 | 要求 | 现状 | 缺口 |
|---|---|---|---|
| **全量层** | 所有实体（票/概念/题材/主题/链/环节/事件/政策/地域/平台/名字族）与所有事实（每日行情、涨停、强度）都要进库，"能全则全" | JSON 分散（universe/concept_map/strength/name_clan）＋ 3 个 CSV | 无统一 schema、无法 SQL、无历史版本、关系缺失 |
| **关系层** | 表达"归属/上下游/别名/共现/同族/龙头-跟风/事件影响" | 只有"概念→链·环节"单层归属 | 无上下游、无共现、无别名、无图查询 |
| **视图层** | 看板只展示当日最强（几个到几十个），一眼看出值得关注 | 双闸＋结构＋盘口＋候选＋补涨 | 缺"主题榜/新晋提醒/下钻关系/数据健康" |

关键判断：**信息损耗不在"没有数据"，而在"数据之间没有边"**。699 个概念、5576 只票、
120,444 条"票-概念"挂靠已经全在库里——缺的是把这些点连成网，并让每天的新事实落进去。

## 一、数据模型（SQLite 单文件，14 张表）

文件：`cache/kb/trading_kb.sqlite`（单文件可备份，SQL 可查，导出 xlsx 直接读它）

### 1.1 维度层（实体）

| 表 | 主键 | 关键字段 | 来源 |
|---|---|---|---|
| `dim_stock` | code | name, 申万1/2/3, 地域, 上市板, 主业项名, 主业链, 主业环节, 市值, 流通市值 | universe + F10 |
| `dim_concept` | concept_id | name, **kind**（概念/题材/主题/事件/政策/地域/平台/人物/产品）, 类目(8类), 链, 环节, 主题域, 子类, 规则, first_seen, last_seen | concept_map + concept_stats |
| `dim_chain` | chain_id | name, desc, 划链原则版本 | pool_config v2.6 |
| `dim_segment` | seg_id | chain_id, name, 词表规模 | pool_config |
| `dim_region` | region_id | 省/市/区域层级 | universe 地域 + REGION 表 |
| `dim_platform` | plat_id | 华为/小米/比亚迪…（平台生态） | concept_map |
| `dim_name_clan` | clan_id | 字/词/谐音/生肖/方位/数字, 族大小 | name_clan |
| `dim_event` | event_id | 类型（政策/并购/业绩/重组/摘帽）, 日期, 标题, 关联概念 | 新增（初期手工+公告） |

### 1.2 关系层（边表，全部带 evidence/source/updated_at）

| 表 | 边 | 语义 | 来源与可信度 |
|---|---|---|---|
| `rel_stock_concept` | 票→概念 | 挂靠（该票属于该概念） | 东财+同花顺（A 级事实） |
| `rel_concept_coord` | 概念→链/环节 | 归位（8 类目） | 自建词表（B 级，可复现） |
| `rel_segment_flow` | 环节→环节 | **上下游**（材料→设备→制造→应用） | **人工定义 DAG**（约 150 条边，B 级）；标注"非公司级供应链" |
| `rel_concept_alias` | 概念↔概念 | 别名/包含（机器人概念≈人形机器人） | 名称归一 + 人工（C 级） |
| `rel_concept_cooccur` | 概念↔概念 | 共现强度（同票挂靠次数/共现率） | 自动统计（A 级事实，解释为 C 级） |
| `rel_concept_lead` | 概念→概念 | 时序领先（A 概念涨停领先 B 概念 N 日） | 自动统计（C 级，需回测） |
| `rel_clan_stock` | 族→票 | 名字族归属 | name_clan（C 级） |
| `rel_theme_parent` | 主题→父坐标 | 主题树挂靠 | 周更生成 + 人工确认 |
| `rel_event_concept` | 事件→概念/票 | 事件影响面 | 事件台账（B 级） |

### 1.3 事实层（每日增量，主键都含 date）

| 表 | 内容 | 保留 |
|---|---|---|
| `fact_snapshot` | 全市场行情（5576×每日：pct/价/量/换手/量比） | 全量保留（约 30MB/年，可压缩） |
| `fact_limitup` | 涨停池（连板/首封/炸板/封单/封成比） | 全量 |
| `fact_concept_daily` | 概念日读数（成员数/涨停数/中位/均值/上涨占比/超额） | 全量 |
| `fact_segment_daily` | 环节/链日读数（同上，一票一归属口径） | 全量 |
| `fact_theme_tree` | 主题树周版本（快照，不覆盖） | 全量 |

### 1.4 元数据与审计

`meta(key,value)`：schema_ver / built_at / 各表行数；
`audit_coverage(date, entity, total, mapped, unmapped_list)`：每日归位审计（未归位清单必须留痕）。

## 二、存储选型（对比后选 SQLite + networkx）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **SQLite + 边表** | 单文件、零服务、SQL 可查、易备份、可导出 | 深图查询要递归 CTE | ✅ **主存储** |
| DuckDB + Parquet | 分析快、列存 | 写入弱、事务弱 | 备选（历史归档） |
| Neo4j | 图查询强 | 要跑服务、运维重、备份麻烦 | ❌ 过重 |
| kuzu（嵌入式图库） | 嵌入式、Cypher | 生态小、导出不便 | 观察 |
| networkx | 现成图算法（社区/中心度） | 内存态，不持久 | ✅ **图计算层**（从边表加载） |

结论：**SQLite 存事实与关系，networkx 做图计算，JSON/CSV 做导出**——本地单机最稳的组合。

## 三、关系从哪来（诚实边界）

1. **能做**：
   - 上下游 DAG：19 链 110 环节人工定义（约 150 条边；如 半导体·材料→设备→制造→封测→芯片应用）；
   - 概念共现：同票挂靠统计（现成数据，今日即可算）；
   - 别名/包含：名称归一 + 人工确认（机器人概念/人形机器人/机器人执行器）；
   - 时序领先：概念涨停序列的领先滞后（需 20 日以上数据，先积累）；
   - 名字族/炒地图/事件：现成。
2. **不能做（不伪造）**：
   - **公司级供应链**（谁给谁供货）：需 Wind/企查查等付费数据，本机没有 → 字段留空、标注"未接入"；
   - 产业链营收占比（某票在环节中的收入占比）：需年报文本挖掘，暂以 F10 主营项近似并标 ≈。

## 四、知识图谱怎么用（不是摆设）

1. **社区发现 → 主题树**：把"概念-概念共现图"跑 Louvain，社区即候选主题簇（替代手工聚类规则），每周跑一次；
2. **中心度 → 枢纽概念**：度中心/介数中心识别"枢纽概念"（如"机器人概念"连接上百条边）→ 提示"泛词/该拆"；
3. **多跳查询**（看板下钻）：`AI眼镜 → 所属环节 → 同环节其他题材 → 当前涨停票` 一条 SQL/两跳图查询；
4. **异常检测**：某概念今日成员涨停率远超历史（p<1%），列为"异动概念"。

## 五、看板 = Top-N 实时视图（只呈现最强）

数据全部来自 DB 的当日切片，**不新增网络请求**：

| 视图 | 规则 | 展示量 |
|---|---|---|
| 双闸 | 已有（A 盘口质量 × B 方向强度） | 固定 |
| **主题榜（新）** | 当日主题按「涨停数 × 超额」排序；新晋/掉出标记 | Top 10 |
| 环节榜 | 一票一归属的环节分布 | Top 10（已有 B 闸 5，可扩展） |
| 新晋提醒（新） | 首现 ≤5 日且涨停≥3 的概念/主题 | Top 5 |
| 异动榜（新） | 涨停率 z-score 前 5 的概念 | Top 5 |
| 个股下钻（增强） | 点票看：挂靠概念→所属链·环节→同环节共振票→名字族 | 单票 |
| 数据健康（新） | 归位率/待归类/数据陈旧度/表行数 | 一行 |

## 七、纪律（与现有体系一致）

1. **不伪造**：供应链/营收占比等未接入数据一律留空标注，不用"看起来合理"的推断填；
2. **证据分级**：每条关系带 `source` + `confidence`（A 事实/B 规则/C 推断）；
3. **版本留痕**：每日 build 写 meta；主题树/链字典按版本存，不覆盖；
4. **可回退**：DB 只读导出 xlsx，看板读 DB 的当日切片——DB 坏了可从原始 JSON 重建；
5. **看板纪律不变**：Top-N 只是视图，判断仍按熔炼系统／A0 纪律。
