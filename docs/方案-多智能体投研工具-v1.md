# 多智能体投研分析工具 · 技术方案 v1（2026-10-25）
## ——从单机看板到「数据流水线 + 审批式智能体」

> 目标形态：App / 网站 / 小程序。本文基于当前产品状态（看板 + 全量库方案 + 知识体系），
> 给出多智能体架构、技术栈、工作流、分期与合规边界。

---

## 一、现有资产盘点（这些是新架构的地基，不重写）

| 资产 | 现状 | 在新架构中的角色 |
|---|---|---|
| 数据层 | universe 5576 / concept_map 699（8 类目）/ 19 链 110 环节 / name_clan / 每日强度 | **事实库**（Postgres）＋ Agent 的检索源 |
| 计算层 | pool_pipeline、intraday_scan、pankou、dual_gate、name_clan、concept_map、daily_strength、universe_audit | **工具集**（每个脚本包成一个 tool，带 JSON schema） |
| 前端 | 单页看板（双闸两卡/涨停结构/盘口/焦点/候选/补涨/同向 + 侧栏/排序/钻取） | **UI 原型**（PWA 化，直接演进） |
| 知识 | 熔炼系统（A 级纪律/层 0–5/相位表）、233/肉肉/波哥/风轻云淡（独立体系）、大盘日报 SOP | **规则库 / Agent 的 system prompt 与判读约束** |
| 评测 | 预判校准账本、事件台账（S0–S3）、快照回归 fullrun.js | **质量评测集**（Agent 输出的对错回填） |

**一句话**：数据、计算、知识、评测都已存在，缺的是"把它们组织成可调用的能力 + 一个有纪律的编排层"。

## 二、目标架构（五层）

```
┌─ 接入层 ─ Web / PWA（先） / 微信小程序（后，需类目资质） / App（最后）
│
├─ API 网关 ── FastAPI + JWT + 限流 + 审计（谁问了什么、看了什么）
│
├─ 编排层 ─── LangGraph（状态机式多智能体 + 人工审批节点）
│              ├ 盘前链：数据→消息→策略→风控 →《今日剧本》
│              ├ 盘中链：盘口读数每 15s；异动触发→推送（不调大模型）
│              └ 盘后链：复盘→归因→知识写回
│
├─ 工具层 ─── 现有脚本包装成 tools（只读为主）
│              查询类：查票/查概念/查链环节/查主题/查供需/查历史
│              计算类：双闸/梯队/强度/名字族/错位度/回测
│              检索类：公告/新闻 RAG、历史复盘检索
│              写入类：只经任务队列 + 人工确认（不直连库）
│
└─ 数据层 ─── PostgreSQL（事实+关系）+ pgvector（语义检索）+ Redis（缓存/队列）
                + Parquet/DuckDB（特征/回测）+ 边表+networkx（图，离线）
```

## 三、八个智能体（职责/输入/输出/频率）

| Agent | 职责 | 输入 | 输出（结构化） | 频率 |
|---|---|---|---|---|
| **数据 Agent** | 采集/清洗/归位/巡检 | 行情/概念/F10/公告/龙虎榜 | 入库 + 覆盖率与异常报告 | 日 |
| **盘口 Agent** | 双闸、情绪周期、梯队、异动 | 当日快照/涨停池 | 双闸读数 + 组合灯 + 异动清单 | 盘中 15s（纯计算）/收盘总结（LLM） |
| **板块 Agent** | 链/环节/题材/主题树强度 | 概念日读数/主题树 | 主线排行 + 新晋/衰退 | 日/周 |
| **个股 Agent** | 画像、归因、错位度、名字族、供需 | 个股全量 | 单票卡片（证据分级） | 按需 |
| **消息 Agent** | 事件分级 S0–S3、影响链 | 公告/新闻/政策 | 四段式（事实/分级/影响链/预案） | 日 + 事件触发 |
| **策略 Agent** | 候选池、补涨、AI 打分 | 上述输出 + 特征 | 候选清单 + 排序 + 理由 | 收盘后 |
| **风控 Agent** | A0 纪律、失效条件、位置核对 | 策略输出 + 熔炼规则 | 通过/否决 + 仓位建议（只给上限） | 每次策略输出后 |
| **复盘 Agent** | 预判回填、三层归因、规则迭代 | 预判账本 + 当日实际 | 命中率报告 + 规则修订建议 | 日/周 |

**编排原则**：
1. **结构化输出优先**：每个 Agent 输出 Pydantic schema（不自由发挥），含 `evidence[]` 与 `confidence(A/B/C)`；
2. **人工在环**：策略→风控→"今日剧本"必须人工确认才推送；任何写库动作走审批；
3. **盘中不调大模型**：15 秒链路只跑确定性计算；LLM 只在收盘后与按需问答；
4. **成本分级**：抽取/摘要用小模型或规则，判断/解释用大模型，结果缓存。

## 四、工作流（投研流水线，不是聊天框）

```
盘前 08:30  数据 Agent 体检（覆盖率/陈旧度/昨日账本）
        ↓
消息 Agent 扫公告/新闻 → S0–S3 分级 → 影响链（题材/环节/个股）
        ↓
策略 Agent 结合双闸/主线/候选池出《预案》 → 风控 Agent 核 A0 → 人工确认
        ↓
盘中 9:25–15:00  盘口 Agent 每 15s 更新读数；异动（新晋主题/涨停加速/龙头断板）推送
        ↓
盘后 15:10  复盘 Agent 对账（预判 vs 实际，✗ 三层归因）→ 知识写回（规则/案例）
```

**问答入口**（辅助，不是主形态）：用户问"今天机器人链为什么强"，个股/板块 Agent 调工具取数 → 带证据回答；答案里必须能看到数据来源与时间。

## 五、技术栈（按阶段）

| 层 | P1（单用户） | P2（小团队） | P3（规模化） |
|---|---|---|---|
| LLM | 云端 API（Claude/GPT/DeepSeek），按需；规则能做的不用模型 | 同左 + 缓存/降级 | 多模型路由 + 私有化小模型 |
| 编排 | **LangGraph**（状态机 + 人工节点） | 同左 + 任务队列 | 同左 + 多租户隔离 |
| 存储 | **PostgreSQL** + pgvector + Redis | 同左（读写分离） | + ClickHouse（明细分析） |
| 图 | 边表 + networkx（离线） | 同左 | **Neo4j**（在线多跳/路径解释） |
| 特征/回测 | Parquet + DuckDB + LightGBM | 同左 | + 特征平台 |
| API | FastAPI + Uvicorn | + Nginx/网关限流 | + K8s/云托管 |
| 前端 | **PWA**（现有看板演进，手机可用） | 同左 | 小程序/App（需资质） |
| 监控 | healthz + 企微告警 | Prometheus + Grafana | 同左 + 审计 |

**为什么 LangGraph 而不是 CrewAI/AutoGen**：投研流程有严格顺序与审批（预判→确认→执行→复盘），状态机可控、可回放、可插入人工节点；自由对话式多智能体难以复现与审计。

## 六、数据模型增量（在 v1.1/v1.2 基础上加 6 张表）

```sql
agent_run(id, agent, started_at, finished_at, model, prompt_ver, cost, status)
agent_output(run_id, kind, payload_json, evidence_json, confidence)   -- 结构化输出
prediction(date, scope, subject, direction, target, invalid_if, source_run)
review(prediction_id, outcome, hit, attribution_layer, note)          -- 复盘回填
tool_call(run_id, tool, args_json, result_hash, latency_ms)           -- 可审计
prompt_version(ver, agent, text, changed_at)                          -- 提示词版本化
```

**关键**：每次 Agent 输出都能追到"哪个模型、哪版提示词、用了哪些工具、证据是什么"——这是投研工具与玩具的分界线。

## 七、分期路线（每期可独立交付）

| 期 | 内容 | 依赖 | 工期 |
|---|---|---|---|
| **P0 底座** | 全量库建库（P1 计划）+ 远程部署（已有方案） | — | 3–4 天 |
| **P1 工具化** | 现有脚本包成 tools（JSON schema）；FastAPI 暴露查询接口；PWA 化看板 | P0 | 1–2 周 |
| **P2 单 Agent** | 先上"盘口 Agent + 复盘 Agent"（确定性最强、最容易验证） | P1 | 1–2 周 |
| **P3 多 Agent 编排** | LangGraph：盘前链/盘后链 + 人工审批 + 推送 | P2 | 2–3 周 |
| **P4 多用户** | PG + Redis + 鉴权/租户 + 限流；小程序/App（含资质） | P3 | 3–4 周 |
| **P5 AI 选股** | 特征库 + LightGBM + 回测 + 候选卡 | P2 | 2–3 周 |

**顺序理由**：先把"确定性计算"做成工具与 Agent（可验证），再上"判断类"Agent；先单用户跑顺，再谈多用户与合规。

## 九、合规与风险（前置，不是收尾）

1. **投顾牌照**：向他人提供具体买卖建议属证券投资咨询，需牌照；工具形态只能是"数据与指标展示 + 模型评分（标注非建议）+ 历史复盘"；
2. **行情数据授权**：东财/同花顺数据不得转售或对外提供；多用户需商用授权；
3. **小程序类目**：金融信息服务需资质，审核严；先做 PWA/公众号 H5 规避类目风险；
4. **LLM 幻觉**：所有输出结构化 + 证据分级 + 数据来源可点开；判断类结论必须人工确认后才推送；
5. **回测过拟合**：purged 时序交叉验证、样本外验证、上线前纸面跟踪 ≥20 交易日；
6. **成本失控**：分级模型 + 缓存 + 每日配额 + 调用审计。
